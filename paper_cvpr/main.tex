\begin{abstract}
Replaying a few hundred stored documents nearly matches joint training when a continual key-information extractor meets new domains, yet fails when its label space grows. We ask why, as an investigation rather than a method. On a class-incremental stream of receipts we test a ladder of hypotheses, each with its prediction stated in advance, and measure where the errors go. Forgetting is not simply harder: with a whole-document memory and a shared softmax the model barely learns the last sessions it is trained on, which naive training learns well. Stale stored labels explain part of the failure: giving the older stored documents their true labels at each boundary leaves the model below joint training (\nOracleN{} so far). Stopping the sharing of the background class closes most of the gap, as existing per-session readouts do: with the same memory and no true labels, one background logit per session reaches $\nSbrFull$ full-label F1 against $\nJointFull$ for joint training. The principle, familiar from training on partially annotated data, is that an ``O'' label is evidence only against the classes its annotator could see. Where label growth supplies the routing key, on a single-schema stream, per-session low-rank trunk updates can replace the memory; across schemas they did not, in our one run.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Key-information extraction (KIE) labels each OCR token of a visually-rich document (form, invoice, receipt), using its words, its 2-D layout and the page image; multimodal encoders such as LayoutLMv3~\citep{huang2022layoutlmv3}, LiLT~\citep{wang2022lilt} and BROS~\citep{hong2022bros} define the state of the art. Deployed extractors meet new document types and growing schemas, while retraining on all history is blocked by cost and by privacy constraints: a continual-learning (CL) problem, whose central obstacle is catastrophic forgetting~\citep{mccloskey1989catastrophic}.

Replay is empirically the strongest remedy in the CL toolbox~\citep{masana2022class,wang2024survey}, and on documents it looks sufficient. On LayoutLMv3, a stream of forms and receipts under one fixed label space is learned by plain replay (ER) with $200$ stored documents to $\nErDil$ AA, against $\nJointDil$ for joint training (App.~F). Let the label space grow instead, by adding CORD's $30$ receipt fields six at a time, and the same method ($\nErCilBuf$ documents) reaches $\nEr$ AA, against $\nJoint$; both ER cells are legacy-protocol runs ($\dagger$) that early-stop on the test split, which favours ER (\cref{sec:setup}). Distillation, prompts, low-rank adapters and the continual-NER methods built for the shift of the ``O'' label do no better (\cref{tab:main}). A class-incremental stream is expected to be harder; what is not obvious is why a memory that holds the old documents does not help. This paper is about that question: \emph{why does replay, which solves domain shift, fail when the label space grows?}

\input{fig/conflict}

We treat it as an investigation (\cref{tab:ladder}): we write down the explanations a reader would offer, state what each predicts before its test, test each with an intervention on the same encoder, stream and recipe, and measure where the final model's errors go (\cref{tab:mech}). Forgetting is not just harder (H0): with a whole-document memory that retains under domain shift, the model suppresses the last sessions it is trained on, which naive training does not do. Stale labels in the memory (H1) are part of the cause: relabelling the older stored documents at each boundary recovers much of the gap but stays below joint training and below the same memory with a per-session background (\nOracleN). Whether what current documents say about old entities is the rest (H2) is open: label-side repairs we ran earlier are preliminary, and a MiB-style unbiased loss on the same memory is the decisive test. Removing the shared background (H3, \cref{fig:conflict}) closes most of the gap with no true labels, given a memory, and then per-session isolation can replace the memory (H4), but only where label growth supplies a routing key.

None of the ingredients is new. The background shift is known from class-incremental segmentation~\citep{cermelli2020mib,douillard2021plop,cha2021ssul}, from incremental detection, where both its stored side~\citep{liu2023abr} and its two-sided form~\citep{mo2024bpf} have been named, and from continual NER~\citep{monaikul2021extendner,zhang2023cpfd,ma2023learning}; separated softmaxes~\citep{ahn2021ssil}, per-task heads with a ``none of mine'' output~\citep{kim2022more} and per-session softmaxes over a constant Other logit~\citep{liu2023ice} already undo the shared normalisation; forgetting in the output-facing layers is known from image classifiers~\citep{ramasesh2021anatomy}. What has not been done is to take apart, on token-labelled documents, why replay fails: which part a memory repairs, which part survives a memory with true labels, and what the errors of each look like.

\paragraph{Contributions.}
\begin{enumerate}
  \item \textbf{The investigation.} A decomposition of why replay fails under label growth that prior work did not run on token-labelled documents: a memory $\times$ readout factorial, the stored-label side reduced by a relabelled memory with the gap that remains, and measurements of where the errors go under each readout (\cref{sec:investigation}): with a shared softmax old entities are missed at ``O'' with or without a memory, and a memory adds a suppressed current session; with a blocked readout and no memory, drift sends them to another session's class through over-claiming blocks. The relabelled-memory control rests on \nOracleN{} so far.
  \item \textbf{An empirical finding, not a new mechanism.} A per-session background readout, as in ICE-O and MORE, combined with whole-document replay and a supervision rule in the spirit of training on disjoint tag sets, closes most of the gap to joint training in continual KIE on every seed, where the continual-NER and replay methods in our comparison do not. Our instantiation (SBR) differs from ICE-O in a learned background per session and in old blocks kept trainable from the memory (\cref{sec:design}).
  \item \textbf{Boundary conditions.} With the conflict removed, per-session low-rank trunk deltas (SBR-Recall) replace the memory on a single-schema stream, within $\nRecallJointGap$ points of joint training on every seed under both metrics, and fail without a memory across annotation schemas (one seed), where the task-identity view says they must (\cref{sec:recall}).
\end{enumerate}

\section{Related Work}
\label{sec:related}
\paragraph{Background shift.} When each step annotates only its own classes, the background label changes meaning. In class-incremental segmentation MiB~\citep{cermelli2020mib} matches a background label with the probability of background or any old class in the loss, and the old model's background with background or any new class in the distillation; PLOP~\citep{douillard2021plop} and SSUL~\citep{cha2021ssul} pseudo-label the background with the old model, and SSUL also freezes the backbone and the past classifiers, keeps a tiny memory and uses per-class sigmoids. Incremental detection has named both sides: replayed images carry current objects in their background (foreground shift~\citep{liu2023abr}), and past and future objects are both labelled background, so the objectives of different stages conflict~\citep{mo2024bpf}. In continual NER the shift of ``O'' is the unlabelled-entity problem~\citep{ma2023learning}, answered by distillation on ``O'' tokens~\citep{monaikul2021extendner,zheng2022cfner}, pseudo-labels with feature distillation~\citep{zhang2023cpfd}, contrastive learning with relabelling~\citep{ma2023learning}, entity-triplet generation~\citep{gencner}, or one binary output per type~\citep{zhang2023spankl}. We do not claim the conflict; we separate its stored and current sides with a relabelled memory and measure what each leaves.

\paragraph{Separated readouts and task identity.} A softmax over old and new classes together biases them, and separating it removes the bias~\citep{ahn2021ssil}; ER-ACE~\citep{caccia2022erace} masks the old classes out of the softmax of incoming samples only. Giving each task its own ``none of mine'' output turns class-incremental learning into within-task prediction plus task identification~\citep{kim2022theoretical}: MORE~\citep{kim2022more} isolates each task's parameters with hard-attention masks on adapters of a frozen pre-trained transformer, trains a head per task whose out-of-distribution output learns from saved samples, and lets the most confident head answer; in class-incremental extraction ICE-O~\citep{liu2023ice} trains, on a frozen encoder and with no memory, one softmax per session over a constant Other logit and that session's types, so that a mention is Other only if every session scores below that logit. SBR is this pattern on documents with a learned background per session and old blocks kept trainable from a memory. SBR-Recall shares MORE's isolation, with per-session low-rank trunk deltas, but trains each block's ``none of mine'' logit on its own session's negatives, with no saved samples. Adapter methods instead merge or combine per-task modules so that no task identity is needed~\citep{zhou2024ease,liang2024inflora,wang2023olora}. Outside CL, taggers trained on datasets with disjoint tag sets either marginalise over the tags a dataset does not annotate~\citep{greenberg2018marginal} or share one tagging layer through a tag hierarchy~\citep{beryozkin2019tagset}; the first is the loss MiB uses, and we make no claim that separation beats it in general.

\paragraph{Latent replay, drift and continual document IE.} REMIND, Latent Replay and generative replay replay mid-network representations through the plastic upper layers~\citep{hayes2020remind,pellegrini2020latent,vandeven2020brain}; exemplar-free methods keep class statistics instead~\citep{zhu2021pass,petit2023fetril,goswami2023fecam,zhang2023slca,chen2023star}. Our memory keeps whole documents, one truncated SVD each, a per-sequence factorisation used to compress key caches~\citep{sun2025shadowkv}. Forgetting in image classifiers sits in the layers nearest the output~\citep{ramasesh2021anatomy}, and in domain-incremental segmentation freezing early layers moves the representation shift to later ones~\citep{kalb2023principles}. Continual relation extraction~\citep{han2020emar,cui2021rpcre,zhao2022crl}, like continual NER, is sentence-level and text-only. Document-level continual learning is recent and small: multimodal LLMs forget under fine-tuning~\citep{zhai2023investigating}, and GDI-Bench~\citep{gdibench} limits it by freezing most parameters; continual table detection~\citep{minouei2022table} uses plain ER; ProtoNER~\citep{kumar2023protoner} adds key-information classes from a few documents with prototypes; AMD-Proj~\citep{sassioui2026amdproj} projects gradients against a memory of task subspaces; and \citet{sassioui2026documents} benchmark layout-aware models by stream regime, finding that no method they test consistently preserves old knowledge under label-space shift and that, for the non-replay methods they test, domain transfer forgets most. They decompose forgetting by regime of the stream; we decompose it by cause, within label growth. The broader CL families~\citep{kirkpatrick2017ewc,li2017lwf,lopezpaz2017gem,buzzega2020der,rebuffi2017icarl,saha2021gpm,wang2022l2p,smith2023coda,mallya2018packnet} are surveyed by \citet{wang2024survey}.

\section{Setup}
\label{sec:setup}
\paragraph{Streams and models.} A document is a triple of OCR tokens, normalised boxes and the page image; the model emits BIO tags per token, scored by entity-level F1 (\texttt{seqeval}). \textbf{CIL-CORD}, the stream of every rung: CORD's $30$ receipt classes arrive six at a time over five sessions; the head grows, and every entity outside the session, earlier or later, is labelled ``O''. \textbf{DIL}: FUNSD$\rightarrow$SROIE$\rightarrow$CORD under one fixed four-entity schema. \textbf{Mixed}: six sessions over three datasets and annotation schemas. LayoutLMv3-base~\citep{huang2022layoutlmv3} is the encoder of every rung; LiLT~\citep{wang2022lilt}, BROS~\citep{hong2022bros} and text-only BERT appear on DIL. Heads are linear. App.~A gives datasets and sessions.

\paragraph{Memory and comparison set.} Every memory-based rung uses one whole-document latent memory (CoLaR, \cref{sec:memory}): $50$ documents per session stored as rank-$128$ SVDs of their layer-$4$ activations, replayed through the upper layers. The comparison set holds naive fine-tuning and joint training as references and one published method per family: ER~\citep{rolnick2019er}, DER++~\citep{buzzega2020der}, LwF~\citep{li2017lwf}, CODA-Prompt~\citep{smith2023coda}, CL-LoRA~\citep{he2025cllora}, LCA~\citep{lca2026}, and the continual-NER methods CPFD~\citep{zhang2023cpfd} and IS3~\citep{qiu2024is3}; App.~G gives their settings and our ports.

\paragraph{Protocol.} AdamW, learning rate $5{\times}10^{-5}$, batch size $2$, seeds 42, 7 and 123. Under the \emph{clean protocol} every session trains in full precision for at most $10$ epochs (joint training: $100$) and early-stops on $10\%$ held out from its \emph{training} data; the test split never selects a model. Cells marked $\dagger$ come from earlier runs (\emph{legacy protocol}) that early-stop on the test split and vary in epoch cap and precision. A cell is clean only when all three clean seeds exist (App.~A, G).

\paragraph{Scoring.} The headline number is the \emph{full-label F1}: the final model on the complete CORD test set with all 30 classes, as in continual NER~\citep{ma2023learning}. Only clean runs record it; against a cell with only AA ($\dagger$, DIL, Mixed) we compare in AA. Retention needs per-session test splits, whose labels show only that session's classes; from $R[i,j]$, the F1 on session $j$ after session $i$, AA $=\tfrac1T\sum_j R[T,j]$. Scored raw, such labels charge a model for every correct entity of another session, so joint training reads $33$ (App.~B); we score each session \emph{session-restricted}, mapping a predicted tag outside session $j$'s label set to ``O'' before span matching. AA averages the sessions, while session~1 holds $\mSessOneShare\%$ of the $\mTestSpans$ test spans; on every seed both metrics order the groups of clean runs the same way (App.~B).

\paragraph{How the settings were chosen.} Tuning and evaluating on the same scenario overstates CL methods~\citep{cha2025hyperparameters}. The comparison set, one published method per family, was fixed after a first grid on all three streams; the methods it dropped then (EWC, L2P, DualPrompt, O-LoRA, ER with C-Flat++) stayed below naive training on every seed of that grid's class-incremental stream (App.~G). The memory settings were chosen on DIL (seed 42; App.~F) and carried unchanged; SBR's claim threshold, $0.5$, was not tuned. The one setting chosen on CIL-CORD is SBR-Recall's delta capacity (App.~D). App.~F lists the buffer-free families and memory variants we built and dropped, with their numbers.

\subsection{H0: is it just harder forgetting?}
\label{sec:h0}
\paragraph{Prediction.} If label growth only made drift harder, the memory that retains under domain shift would still retain here, a raw memory would do better, and the losses would look like naive forgetting, where old sessions are lost and the newest is learned well.

\paragraph{Test and result: refuted.} The CoLaR memory comes within a point of joint training on DIL on average (AA $\nColarDil^\dagger$ against $\nJointDil^\dagger$). On CIL-CORD with a shared softmax it reaches $\vColarFull$ full-label F1 ($\vColar$ AA) against $\vJointFull$ ($\vJoint$). Raw documents do no better (ER, $\nEr$ AA$^\dagger$, below every CoLaR seed), but ER also trains every layer, keeps $200$ documents and is a legacy run, so this row does not isolate memory fidelity. What separates the memory run from naive forgetting is the session being trained: its newest session ends at $\mColarLastMin$ to $\mColarLastMax$ F1, whereas naive training learns every session to at least $\nNaiveDiagMin$ on every seed. It also keeps $\mColarRMin$ to $\mColarRMax\%$ of the old sessions' spans where naive training keeps none, at an old-span precision of at least $\mColarOldPLb\%$ (a lower bound from the exact full-label false positives; \cref{tab:mech}). The type of the lost entities does not separate the two runs. A span-level indicator (not a bound: on one blocked run it reads $\mNoBankBoundMax\%$ where the per-token count is $0$; App.~B) puts $\mColarIndMin$ to $\mColarIndMax\%$ of CoLaR's missed spans entirely at ``O'', and at least $\mNaiveIndMin\%$ of naive training's: a shared softmax misses old entities at ``O'' with or without a memory.

\paragraph{What it rules out, and what it leaves.} Drift alone does not explain the failure: the memory that answers drift on DIL leaves the session being trained suppressed here, which naive training, with all of its drift, does not show. Drift is still real: naive training keeps nothing of the old sessions, and on a fixed label space forgetting sits in the output-facing computation on all four encoders, as known for image classifiers~\citep{ramasesh2021anatomy}; freezing the head and late layers moves it to the early layers rather than removing it (one seed), the mirror image of what \citet{kalb2023principles} report for segmentation. On token-level documents only old-task supervision of the readout repaired it in our experiments, whereas on images class statistics can~\citep{zhang2023slca}. App.~F holds the evidence, with replay against the classical remedies on four encoders.

\subsection{H1: are the stored labels stale?}
\label{sec:h1}
\paragraph{Prediction.} A document stored at session $t$ carries ``O'' on every entity of another session, earlier or later, so the memory itself calls background what the model must keep or learn. In detection the same staleness of replayed examples was named foreground shift and blamed for replay's failure~\citep{liu2023abr}. If these stale labels are the cause, giving the stored documents their true labels should close the gap with the shared softmax unchanged.

\paragraph{Test.} At the end of each session we give every document stored \emph{before} it the true labels of all classes seen so far. The documents of the session just finished keep their own labels until the next boundary, and no refresh can cover the session trained next. The refresh rewrites $\nOracleRelabelTrain$ stale tokens before sessions 3 to 5 (and $\nOracleRelabelAfter$ after the last session, which changes no training; seed 42). It reads labels no continual learner has and is a diagnostic, not a method.

\paragraph{Result: partly.} Against the same memory without the refresh it lifts full-label F1 from $\nColarSeedFull$ to $\nOracleFull$ and AA from $\nColarSeed$ to $\nOracle$ (\nOracleScope): $\nOracleShareFull\%$ and $\nOracleShare\%$ of the seed-matched gap to joint training ($\nJointSeedFull$, $\nJointSeed$), and still below CoLaR-SBR ($\nSbrSeedFull$, $\nSbrSeed$) under both metrics. The metrics disagree because of what the refresh cannot reach. While session $t$ trains, its own classes are ``O'' in every stored document, and sessions 3 to 5 are learned only to $\nOracleLateMin$ to $\nOracleLateMax$ F1 on their own diagonal; sessions 3 and 4 rise to $\nOracleNextMin$ to $\nOracleNextMax$ one session later, once their own documents are stored and the older ones carry their labels, and the last session, which has no later boundary, ends at $\nOracleLast$. AA weights it as a fifth of the score; it holds $\nOracleLastShare\%$ of the test spans.

\paragraph{What it rules out, and what it leaves.} Stale stored labels are a large part of the failure, and they act on the session being trained as much as on old ones: a session suppressed while current and recovered one boundary later is what stale stored labels predict (\nOracleN{} so far), and it marks the limit of this control. Whether a memory that is never stale closes the gap within a shared softmax is what relabelling every stored document \emph{before} each session tests; that control leaves the current documents as the only stale source.

\subsection{H2: do current documents mislabel old entities?}
\label{sec:h2}
\paragraph{Prediction.} A current document labels every entity of an earlier session ``O'', so even a memory with true labels is opposed in every batch by documents that call the same strings background. This is the second side of the conflict named in detection~\citep{mo2024bpf}. If this pull is the cause, a loss that lets a current ``O'' mean ``O or an earlier class'', as MiB does for segmentation~\citep{cermelli2020mib} and marginal-likelihood taggers do offline~\citep{greenberg2018marginal}, should close the gap within a shared softmax. Prior work is mixed on whether a separated readout does better: offline, marginalising over the tags a dataset does not annotate was at least as good as separate outputs per dataset~\citep{greenberg2018marginal}, while in segmentation SSUL's separated sigmoids, with other changes, improved on MiB~\citep{cha2021ssul}.

\paragraph{Test.} The decisive control keeps the memory and the shared softmax and uses MiB's unbiased cross-entropy in both directions: a current ``O'' token matches ``O'' or any earlier-session class, a replayed one ``O'' or any class introduced after storage (no distillation). Its seeds are not complete; until they are, the evidence is the label-side repairs we ran earlier, all legacy runs ($\dagger$, test-split early stopping, which favours them), compared across protocols with clean CoLaR.

\paragraph{Evidence so far: open.} Restricting the replay loss to the classes alive at storage gives $\nSlicedReplayGate$ AA (seed 42). Restricting the current loss as well, so that a current ``O'' token is trained only against ``O'' and the new classes (ER-ACE's asymmetric cross-entropy~\citep{caccia2022erace}, applied to current ``O'' tokens only), lifts seed 42 to $\nSlicedBothGate$, both gate runs: the one same-protocol number specific to this rung. Over three seeds that run averages $\nSlicedBoth$ with a wide spread, and it changes the stored side (H1) and the current side at once. Adding model pseudo-labels on both sides gives $\nPseudoBoth$ (one seed). No repair exceeds $\nLabelRepairMax$ AA on any seed, below every seed of CoLaR-SBR. These runs suggest that the current side matters and do not size it. In the relabelled-memory run old-session recall stays at $\mOracleRMin$ to $\mOracleRMax\%$, against $\mSbrRMin$ to $\mSbrRMax\%$ for CoLaR-SBR (\cref{tab:mech}): the current documents' pull and the stale labels the refresh cannot reach both remain, and refreshing every stored document before each session and the MiB-style loss separate them.

\subsection{H3: is it the shared normalisation?}
\label{sec:h3}
\paragraph{Prediction.} If the conflict lives in the shared normalisation, one background logit trained by documents that disagree about what is background, then one background logit per session, normalised with that session's tags only, should close most of the gap with no true labels. This is SS-IL's diagnosis of a shared softmax~\citep{ahn2021ssil} with a background added, and ICE-O's readout~\citep{liu2023ice} without its frozen encoder. It needs the memory: separating the labels does not undo drift, so without a memory the same readout should fail, and fail the way drift does.

\paragraph{Result: supported, on every seed.} With the memory the session-blocked readout (CoLaR-SBR, \cref{sec:sbr}) reaches $\vSbrFull$ full-label F1 and $\vSbr$ AA, $\nSbrGapFullMin$ to $\nSbrGapFullMax$ full-label points below joint training per seed and above the relabelled memory on every seed both have, under both metrics. The owning block claims $\mSbrOwnerMin$ to $\mSbrOwnerMax\%$ of the old entity tokens, and most remaining errors ($\mSbrSameMin$ to $\mSbrSameMax\%$ of the wrong tokens) give the token another tag of its own session, a B/I swap of the right type included. Without the memory the same readout scores $\vNoBankFull$ ($\vNoBank$ AA), and its errors go elsewhere: not one old entity token is predicted ``O'', $\mNoBankOtherMin$ to $\mNoBankOtherMax\%$ of the wrong ones receive another session's class, and each old block claims $\mNoBankFalseMin$ to $\mNoBankFalseMax\%$ of the tokens of its own split that are not its entities, against $\mSbrFalseMin$ to $\mSbrFalseMax\%$ with the memory. Old blocks on a drifted trunk claim far more than their own entities; that is drift, and the memory reduces it.

\paragraph{The conflict on one receipt.} \Cref{fig:conflict} draws it on look-alike prices. The refresh of H1 removes the stored pull for documents stored before the last boundary; the current documents keep theirs. Under SBR the stored receipt trains only block~1 and the current one only block~5.

\paragraph{What goes against it.} The readout does nothing alone, and it is not free: on DIL, where there is nothing to separate, CoLaR-SBR is below CoLaR (AA $\nSbrDil^\dagger$ against $\nColarDil^\dagger$).

\paragraph{What discriminates what.} Drift (H0) is told apart from the label hypotheses (H1 to H3) by the session being trained, suppressed with a memory and learned without one, and by the same memory coming within $\nSbrGapFullMax$ full-label points of joint training on every seed once the background is not shared. Within the label hypotheses, the relabelled memory measures part of the stored side (H1, \nOracleN{} so far); the current side (H2) and the shared normalisation (H3) are not yet separated, which the MiB-style loss decides. The error type separates drift from conflict only within the blocked readout, memory against no memory: under a shared softmax naive training and CoLaR both miss old entities at ``O'', and those runs saved per-class reports, not per-token outputs.

\section{From diagnosis to design}
\label{sec:design}
\paragraph{The principle.} The rungs point at one fact about annotation under label growth, familiar from training on partially annotated data~\citep{greenberg2018marginal}. A token marked ``O'' in session $s$ means ``none of the classes annotated in session $s$'': it is evidence against those classes and silent about every other. A shared softmax turns it into evidence against all classes at once (H3), and stale stored labels are the same error made by the memory (H1). The principle: \emph{supervise each class only with negatives from documents that annotated it, and normalise together only classes that were annotated together.} Three consequences follow: each session needs its own background; the memory must keep whole documents with their own labels and the session that wrote them; and each session's background logit, trained on that session's true negatives, is also a detector of its entities, so it can route a token without task identity.

\subsection{SBR: one background per session}
\label{sec:sbr}
SBR is our instantiation of a per-session background readout~\citep{liu2023ice,kim2022more}. Every session that brings new tags opens a block $b$ holding those tags $\mathcal{T}_b$. A shared softmax normalises over $\{\mathrm{O}\}\cup\bigcup_b\mathcal{T}_b$. SBR gives every session its own background logit $o_b(x)=w_b^{\top}h(x)+c_b$ on the token feature $h(x)$ and normalises each block separately:
\begin{equation}
p_b(\cdot\mid x)=\operatorname{softmax}\big([\,o_b(x),\,z_{\mathcal{T}_b}(x)\,]\big),
\label{eq:block}
\end{equation}
where $z(x)$ are the tag logits of the usual linear head and $z_{\mathcal{T}_b}(x)$ its entries for the tags in $\mathcal{T}_b$. Within block $b$ a token labelled ``O'' in session-$b$ data is truly background, so the block's supervision is never stale. For a token $x$ with label $y$ in a document of session $s$,
\begin{equation}
\begin{gathered}
\mathcal{L}(x,y,s)=\sum_{b}\,m_{sb}\;\mathrm{CE}\big(p_b(\cdot\mid x),\,y_b\big),\\
y_b=\begin{cases} y & y\in\mathcal{T}_b\\ \mathrm{O}_b & \text{otherwise,}\end{cases}
\end{gathered}
\label{eq:sbr}
\end{equation}
with one rule for the mask: $m_{sb}{=}1$ when session $s$ annotates every tag of $\mathcal{T}_b$; $m_{sb}{=}1$ with $y_b{=}\mathrm{O}_b$ when $b$ belongs to a different annotation schema (the document is annotated under its own schema, so every token is a negative for $b$; a training-time convention that, between related schemas such as SROIE and CORD, can call a real entity background); and $m_{sb}{=}0$ otherwise, because the document's ``O'' labels say nothing about block $b$. Stored documents follow the rule of the session that stored them. A session that adds no tags creates no block, so on a fixed label space SBR has a single block. At inference each block reports its claim $e_b=1-p_b(\mathrm{O}_b\mid x)$; the block with the largest $e_b$ labels the token with its best tag if $e_b>0.5$, and the token is ``O'' otherwise, as in ICE-O's ``Other unless some session scores above it''. Blocks trained at different times need not produce claims on one scale, which is why \cref{tab:mech} measures the routing directly. App.~C gives the pseudo-code, the supervision mode of every (session, block) pair and the memory accounting.

\subsection{The memory}
\label{sec:memory}
SBR's supervision needs stored documents that keep each token's label at its position and the session that wrote it. CoLaR (Compressed Latent Replay) keeps whole documents: after the first session layers $1..k$ are frozen, and each stored document's layer-$k$ activations $H_j$ are kept as a rank-$r$ truncated SVD with its boxes, mask, labels and session, rebuilt at replay and injected at layer $k$. On DIL it retains $\vColarDil^\dagger$ AA in $60$\,MB, against $\vErDil^\dagger$ for ER with $200$ raw documents; it holds no raw pixels or token ids (no privacy claim: activations can leak content). Summaries of the same store fall to the naive level (App.~F).

\subsection{SBR-Recall: the test of H4}
\label{sec:recall}
\paragraph{Prediction (H4).} With the conflict removed, the memory is needed only against drift, and the task-identity view of class-incremental learning~\citep{kim2022theoretical} says when it can go. If each block is read under the trunk state that learned it, nothing drifts for that block and the memory could go, provided the model can tell which state a token belongs to. On one schema under label growth each block's background logit supplies that key. Across schemas the all-background terms of \cref{eq:sbr} train every old block towards background on other-schema documents with nothing to pull it back, so isolation should fail without stored documents; on a fixed label space there is one block and nothing to route by.

\paragraph{The intervention.} SBR-Recall stores, for each session $b>1$, a low-rank delta $\Delta_b$~\citep{hu2022lora} of the layers above $k$ (rank $64$ on the attention projections and feed-forward layers), freezes these layers after the first session (the base $\theta_0$; $\Delta_1{=}0$), and computes block $b$ under the trunk state that learned it:
\begin{equation}
p_b(\cdot\mid x)=\operatorname{softmax}\big([\,o_b,\,z_{\mathcal{T}_b}\,]\big)\big(x;\,\theta_0+\Delta_b\big).
\label{eq:recall}
\end{equation}
Every term of \cref{eq:sbr} is computed under the delta its block is read under, at training and test time. Without a memory on a single-schema stream no term of a later session involves an old block, so each old block's $e_b$ is unchanged up to weight decay, and only competition from new blocks can move its tokens (App.~C).

\paragraph{Result: supported, with its predicted failure.} On CIL-CORD SBR-Recall reaches $\vRecallFull$ full-label F1 ($\vRecall$ AA) with no stored document, within $\nRecallJointGap$ points of joint training on every seed under both metrics; its owning block claims $\mRecallOwnerMin$ to $\mRecallOwnerMax\%$ of the old entity tokens. On Mixed without a memory it scores $\nRecallMixNoMem$ AA$^\dagger$ (seed 42): the blocks of the other schemas fall silent until their domain returns, as predicted, and with the $50$-document memory restored it scores $\nRecallMixMem$ (App.~D). On a fixed label space SBR-Recall has a single block; that it cannot replace the memory there follows from the design and was not run. We ran no shared-softmax counterpart that combines or merges the deltas (as EASE and InfLoRA do); our CL-LoRA port shares one adapter across sessions.

\section{Limitations and conclusion}
\label{sec:limitations}
\label{sec:conclusion}
\paragraph{Limitations.} The study covers three English datasets with test sets of $50$ to $347$ documents and four encoder-only backbones; the ladder, SBR and SBR-Recall are evaluated on LayoutLMv3 and on one class-incremental partition of CORD. The freezing experiment, the memory-content ladder, the relabelled memory (\nOracleN{} so far) and SBR-Recall on Mixed are single- or few-seed diagnostics; H2 rests on legacy runs until its control lands. Errors are split per token only for the blocked readouts; for the shared softmax we have span counts and an indicator. Comparators from this literature that we did not run: a faithful ICE-O (frozen encoder, one head per session, constant Other logit), SBR with a constant background, a separated softmax with one shared background, per-class sigmoid heads (SSUL, SpanKL), MiB's distillation, PLOP and BPF; the MiB-style loss of \cref{sec:h2} is the background-shift correction we queue on the same memory. Joint training is a reference, not a bound. SBR-Recall grows by one delta and one pass per session and freezes its base after session~1, so it may depend on the session order. SBR's rule reads each session's schema at training time. CoLaR's memory grows with the sessions, and storing no raw pixels or token ids is weaker than privacy.

\paragraph{Conclusion.} Replay retains documents under domain shift and fails under label growth because two things go wrong, and a memory repairs only one. Drift is answered by a whole-document memory. The background conflict is not: stale stored labels are part of it, and relabelling the older stored documents with their true labels leaves a shared softmax below joint training and below CoLaR-SBR (\nOracleN); whether the current documents' labels are the rest is open. Under a shared softmax old entities are missed at ``O'' with or without a memory, so there the error type does not tell the causes apart; what separates the conflict from drift is a suppressed current session that the memory does not cure. Most of the conflict is removed at the readout, by letting an ``O'' label count only against the classes its annotator could see, and where label growth supplies the routing key that readout lets per-session deltas replace the memory. Continual document methods should be tested on a growing label space, with a mask-free metric, against a memory whose stale labels are refreshed.
