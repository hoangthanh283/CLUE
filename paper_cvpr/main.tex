\begin{abstract}
Replaying a few hundred stored documents nearly matches joint training when a continual key-information extractor meets new domains, yet collapses when its label space grows. We ask why, as an investigation rather than a method. On a class-incremental stream of receipts we test a ladder of hypotheses, each with its prediction stated in advance, and measure where the errors go. Forgetting is not simply harder: with a whole-document memory and a shared softmax, the old entities it still predicts are mostly right, but most are missed, and the newest sessions are barely learned. Stale stored labels explain part of it, but no memory we tried removes the failure: giving the older stored documents their true labels at each boundary still leaves the model below joint training (\nOracleN). What removes it is to stop sharing the background class, as existing per-session readouts do: with the same memory and no true labels, one background logit per session reaches $\nSbrFull$ full-label F1 against $\nJointFull$ for joint training. The principle, familiar from training on partially annotated data, is that an ``O'' label is evidence only against the classes its annotator could see. Where label growth supplies the routing key, on a single-schema stream, per-session low-rank trunk updates can then replace the memory; across schemas they cannot.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Key-information extraction (KIE) labels each OCR token of a visually-rich document (form, invoice, receipt), using its words, its 2-D layout and the page image; multimodal encoders such as LayoutLMv3~\citep{huang2022layoutlmv3}, LiLT~\citep{wang2022lilt} and BROS~\citep{hong2022bros} define the state of the art. Deployed extractors meet new document types and growing schemas, while retraining on all history is blocked by cost and by privacy constraints: a continual-learning (CL) problem, whose central obstacle is catastrophic forgetting~\citep{mccloskey1989catastrophic}.

Replay is empirically the strongest remedy in the CL toolbox~\citep{masana2022class,wang2024survey}, and on documents it looks sufficient. On LayoutLMv3, a stream of forms and receipts under one fixed label space is learned by plain replay (ER) with $200$ stored documents to $\nErDil$ AA, against $\nJointDil$ for joint training (\cref{tab:dil}). Let the label space grow instead, by adding CORD's $30$ receipt fields six at a time, and the same method ($\nErCilBuf$ documents) reaches $\nEr$ AA, against $\nJoint$; both ER cells are legacy-protocol runs ($\dagger$) that early-stop on the test split, which favours ER (\cref{sec:setup}). Distillation, prompts, low-rank adapters and the continual-NER methods built for the shift of the ``O'' label do no better (\cref{tab:main}). A class-incremental stream is expected to be harder; what is not obvious is why a memory that holds the old documents does not help. This paper is about that question: \emph{why does replay, which solves domain shift, fail when the label space grows?}

We treat it as an investigation (\cref{tab:ladder}): we write down the explanations a reader would offer, state what each predicts before its test, test each with an intervention that changes one thing on the same encoder, stream and recipe, and measure where the final model's errors go (\cref{tab:mech}). Forgetting is not just harder (H0): a whole-document memory that retains under domain shift misses most old entities and suppresses the session being trained, which drift does not do. Stale labels in the memory (H1) are part of the cause: relabelling the older stored documents at each boundary recovers much of the gap but stays below joint training and below the same memory with the readout introduced here (\nOracleN). Label-side corrections of what current documents say about old entities (H2) recovered part of the gap; a MiB-style unbiased loss on the same memory is the decisive test of that rung. Removing the shared background (H3) closes most of the gap with no true labels, given a memory, and then per-session isolation can replace the memory (H4), but only where label growth supplies a routing key.

None of the ingredients is new. The background shift is known from class-incremental segmentation~\citep{cermelli2020mib,douillard2021plop,cha2021ssul}, from incremental detection, where both its stored side~\citep{liu2023abr} and its two-sided form~\citep{mo2024bpf} have been named, and from continual NER~\citep{monaikul2021extendner,zhang2023cpfd,ma2023learning}; separated softmaxes~\citep{ahn2021ssil}, per-task heads with a ``none of mine'' output~\citep{kim2022more} and per-session softmaxes over a constant Other logit~\citep{liu2023ice} already undo the shared normalisation; forgetting in the output-facing layers is known from image classifiers~\citep{ramasesh2021anatomy}. What has not been done is to take apart, on token-labelled documents, why replay fails: which part a memory repairs, which part survives a memory with true labels, and what the errors of each look like.

\paragraph{Contributions.}
\begin{enumerate}
  \item \textbf{The investigation.} A decomposition of why replay fails under label growth that prior work did not run on token-labelled documents: a memory $\times$ readout factorial, the stored-label side removed by a relabelled memory with the gap that remains, and direct measurements that tell the causes apart (drift sends old entities to another session's class through over-claiming blocks; the conflict leaves them missed and suppresses the session being trained; \cref{sec:investigation}). The relabelled-memory control rests on \nOracleN{} so far.
  \item \textbf{An empirical finding, not a new mechanism.} A per-session background readout, as in ICE-O and MORE, combined with whole-document replay and a supervision rule in the spirit of training on disjoint tag sets, closes most of the gap to joint training in continual KIE on every seed, where the continual-NER and replay methods in our comparison do not. Our instantiation (SBR) differs from ICE-O in a learned background per session and in old blocks kept trainable from the memory (\cref{sec:design}).
  \item \textbf{Boundary conditions.} With the conflict removed, per-session low-rank trunk deltas (SBR-Recall) replace the memory on a single-schema stream, within $\nRecallJointGap$ points of joint training on every seed under both metrics, and fail without a memory across annotation schemas (one seed), where the task-identity view says they must (\cref{sec:recall}).
\end{enumerate}

\section{Related Work}
\label{sec:related}
\paragraph{Background shift.} When each step annotates only its own classes, the background label changes meaning. In class-incremental segmentation MiB~\citep{cermelli2020mib} matches a background label with the probability of background or any old class in the loss, and the old model's background with background or any new class in the distillation; PLOP~\citep{douillard2021plop} and SSUL~\citep{cha2021ssul} pseudo-label the background with the old model, and SSUL also freezes the backbone and the past classifiers, keeps a tiny memory and uses per-class sigmoids. Incremental detection has named both sides: replayed images carry current objects in their background (foreground shift~\citep{liu2023abr}), and past and future objects are both labelled background, so the objectives of different stages conflict~\citep{mo2024bpf}. In continual NER the shift of ``O'' is the unlabelled-entity problem~\citep{ma2023learning}, answered by distillation on ``O'' tokens~\citep{monaikul2021extendner,zheng2022cfner}, pseudo-labels with feature distillation~\citep{zhang2023cpfd}, contrastive learning with relabelling~\citep{ma2023learning}, entity-triplet generation~\citep{gencner}, or one binary output per type~\citep{zhang2023spankl}. We do not claim the conflict; we separate its stored and current sides with a relabelled memory and measure what each leaves.

\paragraph{Separated readouts and task identity.} A softmax over old and new classes together biases them, and separating it removes the bias~\citep{ahn2021ssil}. Giving each task its own ``none of mine'' output turns class-incremental learning into within-task prediction plus task identification~\citep{kim2022theoretical}: MORE~\citep{kim2022more} trains a head per task with an out-of-distribution output on saved samples and lets the most confident head answer, and in class-incremental extraction ICE-O~\citep{liu2023ice} trains, on a frozen encoder and with no memory, one softmax per session over a constant Other logit and that session's types, so that a mention is Other only if every session scores below that logit. SBR is this pattern on documents with a learned background per session and old blocks kept trainable from a memory; SBR-Recall adds per-session trunk deltas. Adapter methods instead merge or combine per-task modules so that no task identity is needed~\citep{zhou2024ease,liang2024inflora,wang2023olora}. Outside CL, taggers trained on datasets with disjoint tag sets either marginalise over the tags a dataset does not annotate~\citep{greenberg2018marginal} or share one tagging layer through a tag hierarchy~\citep{beryozkin2019tagset}; the first is the loss MiB uses, and we make no claim that separation beats it in general.

\paragraph{Latent and compressed replay.} REMIND~\citep{hayes2020remind}, Latent Replay~\citep{pellegrini2020latent} and generative replay~\citep{vandeven2020brain} replay stored or generated mid-network representations through the plastic upper layers. Exemplar-free methods keep class statistics: PASS and FeTrIL generate old-class features from prototypes~\citep{zhu2021pass,petit2023fetril}, FeCAM classifies by a per-class Mahalanobis distance on a frozen backbone~\citep{goswami2023fecam}, SLCA realigns the classifier with class Gaussians~\citep{zhang2023slca}, and in segmentation replaying class prototypes rivals image replay~\citep{chen2023star}. A document carries one label per token, bound to its position and its page; our memory keeps that with one truncated SVD per document, a per-sequence factorisation used to compress key caches~\citep{sun2025shadowkv}, here used as a replay memory.

\paragraph{Where forgetting lives; continual document IE.} \citet{ramasesh2021anatomy} localise forgetting in image classifiers to the layers nearest the output; \citet{kalb2023principles} find that in domain-incremental segmentation freezing early layers moves the representation shift to later layers rather than removing it. Continual relation extraction~\citep{han2020emar,cui2021rpcre,zhao2022crl}, like continual NER, is sentence-level and text-only. Document-level continual learning is recent and small: GDI-Bench~\citep{gdibench} limits forgetting in multimodal-LLM fine-tuning by freezing most parameters; continual table detection~\citep{minouei2022table} uses plain ER; ProtoNER~\citep{kumar2023protoner} adds key-information classes to a LayoutLM-family model from a few documents with prototypical networks; AMD-Proj~\citep{sassioui2026amdproj} projects gradients against a memory of task subspaces on FUNSD, SROIE, CORD and BuDDIE; and \citet{sassioui2026documents} benchmark forgetting of layout-aware models on the same datasets by stream regime (domain transfer, layout drift, schema evolution), finding that no method they test preserves old knowledge under label-space shift. They decompose forgetting by regime of the stream; we decompose it by cause, within label growth. The broader CL families~\citep{kirkpatrick2017ewc,li2017lwf,lopezpaz2017gem,buzzega2020der,rebuffi2017icarl,saha2021gpm,wang2022l2p,smith2023coda,mallya2018packnet} are surveyed by \citet{wang2024survey}.

\section{Setup}
\label{sec:setup}
\paragraph{Task and streams.} A document is a triple of OCR tokens, normalised boxes and the page image; the model emits BIO tags per token and is scored by entity-level F1 (\texttt{seqeval}). We use FUNSD (149/50 train/test forms), CORD (800/100/100 receipts, 30 classes) and SROIE (626/347 receipts). \textbf{DIL}: FUNSD$\rightarrow$SROIE$\rightarrow$CORD under one fixed four-entity schema; only the input distribution shifts. \textbf{CIL-CORD}: CORD's 30 classes arrive six at a time over five sessions; the head grows, and tokens of every class outside the session, earlier or later, are labelled ``O''. \textbf{Mixed}: six sessions over three datasets and annotation schemas (two class-incremental FUNSD sessions, a shift to SROIE, two class-incremental sessions on CORD's super-classes, a FUNSD revisit with all its labels). App.~A gives the sessions.

\paragraph{Backbones, memory and comparison set.} LayoutLMv3-base~\citep{huang2022layoutlmv3} is the primary encoder; LiLT~\citep{wang2022lilt}, BROS~\citep{hong2022bros} and text-only BERT are secondary. Heads are linear. Every memory-based run of the investigation uses one whole-document latent memory (CoLaR, \cref{sec:memory}): after the first session the embeddings and layers $1..4$ are frozen, and $50$ documents per session (per task on DIL) are stored as a rank-$128$ truncated SVD of their layer-$4$ activations with their boxes and labels and replayed through the upper layers, four per step. The comparison set is fixed in advance: naive fine-tuning and joint training as references, and one published method per family: ER~\citep{rolnick2019er} and DER++~\citep{buzzega2020der}, LwF~\citep{li2017lwf}, CODA-Prompt~\citep{smith2023coda}, CL-LoRA~\citep{he2025cllora}, LCA~\citep{lca2026}, and the continual-NER methods CPFD~\citep{zhang2023cpfd} and IS3~\citep{qiu2024is3}. Replay baselines keep $200$ raw documents (DER++ $\alpha{=}\beta{=}0.5$); in clean-protocol cells ER instead keeps as many as our memory. LwF uses $T{=}2$. Our CL-LoRA port trains a single rank-$8$ adapter on the attention projections of the frozen encoder, shared by all sessions, unlike the published design, which pairs task-shared and task-specific adapters; its numbers describe this port.

\paragraph{Training protocol.} AdamW, learning rate $5{\times}10^{-5}$, weight decay $0.01$, gradient clipping $1.0$, batch size $2$, seeds 42, 7 and 123. Under the \emph{clean protocol} every session trains in full precision for at most $10$ epochs (joint training: $100$), with early stopping (patience $2$) on a $10\%$ split held out from that session's \emph{training} data and scored with the same session restriction as the test, so a prediction of another session's class is neither rewarded nor charged; the test split is never used for model selection. Cells marked $\dagger$ come from earlier runs (the \emph{legacy protocol}), which early-stop on the session's test split (except joint training on Mixed) and vary in epoch cap ($10$ to $100$) and precision. A cell switches to the clean protocol only when all three clean seeds exist and never combines the two; App.~G lists the settings of every $\dagger$ cell.

\paragraph{Scoring.} The headline number is the \emph{full-label F1}: the final model on the complete CORD test set with all 30 classes, the usual evaluation of continual NER~\citep{ma2023learning}. Only clean runs record it; a comparison with a cell that has only AA ($\dagger$ cells, DIL, Mixed) is made in AA on both sides. Retention needs per-session test sets, whose labels show only that session's classes; from the retention matrix $R[i,j]$ (F1 on session $j$ after session $i$) we report AA $=\tfrac1T\sum_j R[T,j]$. Scoring raw predictions against such labels is a pitfall: a model that correctly labels another session's entity is charged a false positive in every session that does not own it, so a jointly trained model reads $33$ (App.~B). We score each session \emph{session-restricted}: a predicted tag outside session $j$'s label set becomes ``O'' before span matching, so an error is charged at most once. The two metrics weight differently: AA averages the sessions, while session~1 holds $\mSessOneShare\%$ of the $\mTestSpans$ test spans. Pooling a final model's per-session span counts reproduces its full-label F1 within $\mPoolGapMax$ points, except for the blocked readout without memory, whose false positives on other sessions' receipts the splits omit; on every seed both metrics order the groups of clean runs the same way (App.~B).

\paragraph{How the settings were chosen.} Tuning and evaluating on the same scenario overstates CL methods~\citep{cha2025hyperparameters}, so we state how each setting was fixed. The comparison set was fixed before the class-incremental runs, one method per family. The memory settings ($k{=}4$, $r{=}128$, $50$ documents) were chosen on DIL with LayoutLMv3 (seed 42; App.~F) and carried unchanged to every class-incremental stream. SBR's claim threshold is $0.5$ and was not tuned (tuning it on the test set moves AA by at most $0.6$; \cref{sec:beyond}). The one setting chosen on CIL-CORD is SBR-Recall's delta capacity: rank $8$ on the attention projections left two sessions under-learned in legacy runs that early-stopped on the test split, and we adopted rank $64$ with the feed-forward layers before the clean re-runs (App.~D). We also built and dropped five buffer-free families, memory summaries, read-side memory additions, rebalancing, lexical routing, budget allocation, public-proxy replay and an SBR variant without its cross-schema rule; App.~F lists each with its numbers and failure reason.

\subsection{H0: is it just harder forgetting?}
\label{sec:h0}
\paragraph{Prediction.} If label growth only made drift harder, the memory that retains under domain shift would still retain here, a raw memory would do better, and the losses would look like naive forgetting, where old sessions are lost and the newest is learned well.

\paragraph{Test and result: refuted.} The CoLaR memory comes within a point of joint training on DIL on average (AA $\nColarDil$ against $\nJointDil$, \cref{tab:main}). On CIL-CORD with a shared softmax it reaches $\vColarFull$ full-label F1 ($\vColar$ AA) against $\vJointFull$ ($\vJoint$), and raw documents do no better (ER, $\nEr$ AA$^\dagger$, below every CoLaR seed). The errors do not look like naive forgetting. The full-label F1 and the exact span counts imply a precision of $\mColarImpPMin$ to $\mColarImpPMax\%$ over all sessions, but the model finds only $\mColarRMin$ to $\mColarRMax\%$ of the old sessions' spans (\cref{tab:mech}); a span-level bound puts at least $\mColarMissedOMin\%$ of its missed spans entirely at ``O'' (an indicator: its assumption fails on one blocked run, App.~B). And the newest session ends at $\mColarLastMin$ to $\mColarLastMax$ F1, whereas naive training, which forgets every old session, learns every session to at least $\nNaiveDiagMin$. With a memory the model mostly misses old entities rather than confusing them, and it misses those of the session it is training too.

\paragraph{What it rules out, and what it leaves.} Memory fidelity is not the bottleneck, since raw documents do no better. Drift is still real: naive training keeps nothing of the old sessions, and on a fixed label space forgetting sits in the output-facing computation on all four encoders, as known for image classifiers~\citep{ramasesh2021anatomy}; freezing the head and late layers moves the drift to the early layers rather than removing it (one seed), the mirror image of what \citet{kalb2023principles} report for segmentation. On token-level documents only old-task supervision of the readout repaired it in our experiments, whereas on images class statistics can~\citep{zhang2023slca}; \cref{tab:dil} and App.~F hold the evidence.

\subsection{H1: are the stored labels stale?}
\label{sec:h1}
\paragraph{Prediction.} A document stored at session $t$ carries ``O'' on every entity of another session, earlier or later, so the memory itself calls background what the model must keep or learn. In detection the same staleness of replayed examples was named foreground shift and blamed for replay's failure~\citep{liu2023abr}. If these stale labels are the cause, giving the stored documents their true labels should close the gap with the shared softmax unchanged.

\paragraph{Test.} At the end of each session we give every document stored \emph{before} it the true labels of all classes seen so far. The documents of the session just finished keep their own labels until the next boundary, and no refresh can cover the session trained next. The refresh rewrites $\nOracleRelabelTrain$ stale tokens before sessions 3 to 5 (and $\nOracleRelabelAfter$ after the last session, which changes no training; seed 42). It reads labels no continual learner has and is a diagnostic, not a method.

\paragraph{Result: partly.} Against the same memory without the refresh it lifts full-label F1 from $\nColarSeedFull$ to $\nOracleFull$ and AA from $\nColarSeed$ to $\nOracle$ (\nOracleScope): $\nOracleShareFull\%$ and $\nOracleShare\%$ of the seed-matched gap to joint training ($\nJointSeedFull$, $\nJointSeed$), and still below CoLaR-SBR ($\nSbrSeedFull$, $\nSbrSeed$) under both metrics. The metrics disagree because of what the refresh cannot reach. While session $t$ trains, its own classes are ``O'' in every stored document, and sessions 3 to 5 are learned only to $\nOracleLateMin$ to $\nOracleLateMax$ F1 on their own diagonal; sessions 3 and 4 rise to $\nOracleNextMin$ to $\nOracleNextMax$ one session later, once their own documents are stored and the older ones carry their labels, and the last session, which has no later boundary, ends at $\nOracleLast$. AA weights it as a fifth of the score; it holds $\nOracleLastShare\%$ of the test spans.

\paragraph{What it rules out, and what it leaves.} Stale stored labels are a large part of the failure, and they act on the session being trained as much as on old ones: a session suppressed while current and recovered one boundary later is the stale-label mechanism seen directly, and the limit of this control. Whether a memory that is never stale closes the gap within a shared softmax is what relabelling every stored document \emph{before} each session tests; that control leaves the current documents as the only stale source.

\subsection{H2: do current documents mislabel old entities?}
\label{sec:h2}
\paragraph{Prediction.} A current document labels every entity of an earlier session ``O'', so even a memory with true labels is opposed in every batch by documents that call the same strings background. This is the second side of the conflict named in detection~\citep{mo2024bpf}. If this pull is the cause, a loss that lets a current ``O'' mean ``O or an earlier class'', as MiB does for segmentation~\citep{cermelli2020mib} and marginal-likelihood taggers do offline~\citep{greenberg2018marginal}, should close the gap within a shared softmax; prior work gives no reason to expect a separated readout to do better than it.

\paragraph{Test.} The decisive control keeps the memory and the shared softmax and uses MiB's unbiased cross-entropy in both directions: a current ``O'' token matches ``O'' or any earlier-session class, a replayed one ``O'' or any class introduced after storage (no distillation). Its seeds are not complete; until they are, the evidence is the label-side repairs we ran earlier, all legacy runs ($\dagger$, test-split early stopping, which favours them).

\paragraph{Evidence so far: partly.} Restricting the replay loss to the classes alive at storage gives $\nSlicedReplayGate$ AA (seed 42); restricting the current loss as well, so that a current ``O'' token is trained only against ``O'' and the new classes, gives $\nSlicedBoth$ on average over three seeds; adding model pseudo-labels on both sides, as the pseudo-labelling methods do, gives $\nPseudoBoth$ (one seed). No repair exceeds $\nLabelRepairMax$ AA on any seed, below every seed of CoLaR-SBR. In the relabelled-memory run old-session recall stays at $\mOracleRMin\%$, against $\mSbrRMin$ to $\mSbrRMax\%$ for CoLaR-SBR (\cref{tab:mech}); the current documents' pull is the remaining suspect, and the MiB-style control measures how much of it a corrected loss removes.

\subsection{H3: is it the shared normalisation?}
\label{sec:h3}
\paragraph{Prediction.} If the conflict lives in the shared normalisation, one background logit trained by documents that disagree about what is background, then one background logit per session, normalised with that session's tags only, should close most of the gap with no true labels. This is SS-IL's diagnosis of a shared softmax~\citep{ahn2021ssil} with a background added, and ICE-O's readout~\citep{liu2023ice} without its frozen encoder. It needs the memory: separating the labels does not undo drift, so without a memory the same readout should fail, and fail the way drift does.

\paragraph{Result: supported, on every seed.} With the memory the session-blocked readout (CoLaR-SBR, \cref{sec:sbr}) reaches $\vSbrFull$ full-label F1 and $\vSbr$ AA, $\nSbrGapFullMin$ to $\nSbrGapFullMax$ full-label points below joint training per seed and above the relabelled memory on every seed both have, under both metrics. The owning block claims $\mSbrOwnerMin$ to $\mSbrOwnerMax\%$ of the old entity tokens, and most remaining errors ($\mSbrSameMin$ to $\mSbrSameMax\%$ of the wrong tokens) are confusions inside a session. Without the memory the readout scores $\vNoBankFull$ ($\vNoBank$ AA), with the other signature: not one old entity token is predicted ``O'', $\mNoBankOtherMin$ to $\mNoBankOtherMax\%$ of the wrong ones receive another session's class, and each old block claims $\mNoBankFalseMin$ to $\mNoBankFalseMax\%$ of the tokens of its own split that are not its entities, against $\mSbrFalseMin$ to $\mSbrFalseMax\%$ with the memory. Old blocks on a drifted trunk claim far more than their own entities; that is drift, and the memory removes it.

\paragraph{The conflict on one receipt.} Take a receipt stored at the end of session~1, when only menu fields exist: its item prices are labelled \texttt{menu.price} and its total price ``O''. In session~5 a current receipt labels its total price \texttt{total.total\_price} and its item prices ``O'', since menu fields are not annotated in that session. In one batch the two supervise the one background logit of a shared softmax on look-alike price strings, the stored receipt pulling totals towards ``O'' and the current one pulling item prices towards it. The refresh removes the first pull for the documents stored before the last boundary; the current documents keep the second. Under SBR the stored receipt trains only block~1 and the current one only block~5, so neither pulls the other's background.

\paragraph{What goes against it.} The readout does nothing alone, and it is not free: on DIL, where there is nothing to separate, CoLaR-SBR is below CoLaR (AA $\nSbrDil$ against $\nColarDil$$^\dagger$).

\paragraph{What the measurements do not show.} The shared-softmax runs saved per-class reports, not per-token outputs, so their errors are not split by type. Block measurements use session-masked splits whose ``O'' tokens include other sessions' entities, so we count only claims by a split's own block, wrong whatever the token is.

\section{From diagnosis to design}
\label{sec:design}
\paragraph{The principle.} The rungs point at one fact about annotation under label growth, familiar from training on partially annotated data~\citep{greenberg2018marginal}. A token marked ``O'' in session $s$ means ``none of the classes annotated in session $s$'': it is evidence against those classes and silent about every other. A shared softmax turns it into evidence against all classes at once (H3), and stale stored labels are the same error made by the memory (H1). The principle: \emph{supervise each class only with negatives from documents that annotated it, and normalise together only classes that were annotated together.} Three consequences follow: each session needs its own background; the memory must keep whole documents with their own labels and the session that wrote them; and each session's background logit, trained on that session's true negatives, is also a detector of its entities, so it can route a token without task identity.

\subsection{SBR: one background per session}
\label{sec:sbr}
SBR is our instantiation of a per-session background readout~\citep{liu2023ice,kim2022more}. Every session that brings new tags opens a block $b$ holding those tags $\mathcal{T}_b$. A shared softmax normalises over $\{\mathrm{O}\}\cup\bigcup_b\mathcal{T}_b$. SBR gives every session its own background logit $o_b(x)=w_b^{\top}h(x)+c_b$ on the token feature $h(x)$ and normalises each block separately:
\begin{equation}
p_b(\cdot\mid x)=\operatorname{softmax}\big([\,o_b(x),\,z_{\mathcal{T}_b}(x)\,]\big),
\label{eq:block}
\end{equation}
where $z(x)$ are the tag logits of the usual linear head and $z_{\mathcal{T}_b}(x)$ its entries for the tags in $\mathcal{T}_b$. Within block $b$ a token labelled ``O'' in session-$b$ data is truly background, so the block's supervision is never stale. For a token $x$ with label $y$ in a document of session $s$,
\begin{equation}
\begin{gathered}
\mathcal{L}(x,y,s)=\sum_{b}\,m_{sb}\;\mathrm{CE}\big(p_b(\cdot\mid x),\,y_b\big),\\
y_b=\begin{cases} y & y\in\mathcal{T}_b\\ \mathrm{O}_b & \text{otherwise,}\end{cases}
\end{gathered}
\label{eq:sbr}
\end{equation}
with one rule for the mask: $m_{sb}{=}1$ when session $s$ annotates every tag of $\mathcal{T}_b$; $m_{sb}{=}1$ with $y_b{=}\mathrm{O}_b$ when $b$ belongs to a different annotation schema (the document is annotated under its own schema, so every token is a negative for $b$; a training-time convention that, between related schemas such as SROIE and CORD, can call a real entity background); and $m_{sb}{=}0$ otherwise, because the document's ``O'' labels say nothing about block $b$. Stored documents follow the rule of the session that stored them. A session that adds no tags creates no block, so on a fixed label space SBR has a single block. At inference each block reports its claim $e_b=1-p_b(\mathrm{O}_b\mid x)$; the block with the largest $e_b$ labels the token with its best tag if $e_b>0.5$, and the token is ``O'' otherwise, as in ICE-O's ``Other unless some session scores above it''. Blocks trained at different times need not produce claims on one scale, which is why \cref{tab:mech} measures the routing directly. App.~C gives the pseudo-code, the supervision mode of every (session, block) pair and the memory accounting.

\subsection{The memory}
\label{sec:memory}
SBR's supervision needs stored documents that keep each token's label at its position and the session that wrote it. The memory we use, CoLaR (Compressed Latent Replay), keeps whole documents and compresses each one on its own. The pooled layer-$k$ feature space is close to full rank, but one document's tokens share a layout and a vocabulary, so its activation matrix $H_j\in\mathbb{R}^{N_j\times d}$ is low-rank; CoLaR stores $H_j\approx U_r\Sigma_rV_r^{\top}$ with the document's boxes, mask, labels and session, rebuilds $\hat H_j$ at replay and injects it at layer $k$. On DIL it retains $\vColarDil$ AA in $60$\,MB ($1$\,MB $=10^6$ bytes), against $\vErDil$ for ER with $200$ raw documents, and it holds no raw pixels or token ids (no privacy claim: activations can leak content). Summaries of the same store injected below the self-attention layers (pooled spectral summaries, per-class Gaussians, centroids) fall to the naive level, as per-class Gaussian latent replay does on images; a class statistic used at the readout works on images~\citep{zhang2023slca}, while the readout-level Gaussian realignment we ran on documents (LCA's, after merging) does not repair drift (App.~F, which holds the ladder, the compression trade-off and the image comparison).

\subsection{SBR-Recall: the test of H4}
\label{sec:recall}
\paragraph{Prediction (H4).} With the conflict removed, the memory is needed only against drift, and the task-identity view of class-incremental learning~\citep{kim2022theoretical} says when it can go. If each block is read under the trunk state that learned it, nothing drifts for that block and the memory could go, provided the model can tell which state a token belongs to. On one schema under label growth each block's background logit supplies that key. Across schemas the all-background terms of \cref{eq:sbr} train every old block towards background on other-schema documents with nothing to pull it back, so isolation should fail without stored documents; on a fixed label space there is one block and nothing to route by.

\paragraph{The intervention.} SBR-Recall stores, for each session $b>1$, a low-rank delta $\Delta_b$~\citep{hu2022lora} of the layers above $k$ (rank $64$ on the attention projections and feed-forward layers), freezes these layers after the first session (the base $\theta_0$; $\Delta_1{=}0$), and computes block $b$ under the trunk state that learned it:
\begin{equation}
p_b(\cdot\mid x)=\operatorname{softmax}\big([\,o_b,\,z_{\mathcal{T}_b}\,]\big)\big(x;\,\theta_0+\Delta_b\big).
\label{eq:recall}
\end{equation}
Every term of \cref{eq:sbr} is computed under the delta its block is read under, at training and test time. Without a memory on a single-schema stream no term of a later session involves an old block, so each old block's $e_b$ is unchanged up to weight decay, and only competition from new blocks can move its tokens (App.~C). A session that adds no block reuses the delta of the first block it trains fully.

\paragraph{Result: supported, with its predicted failure.} On CIL-CORD SBR-Recall reaches $\vRecallFull$ full-label F1 ($\vRecall$ AA) with no stored document, within $\nRecallJointGap$ points of joint training on every seed under both metrics; its owning block claims $\mRecallOwnerMin$ to $\mRecallOwnerMax\%$ of the old entity tokens. On Mixed without a memory it scores $\nRecallMixNoMem$ AA$^\dagger$ (seed 42): the blocks of the other schemas fall silent until their domain returns, as predicted, and with the $50$-document memory restored it scores $\nRecallMixMem$ (App.~D). On a fixed label space SBR-Recall has a single block; that it cannot replace the memory there follows from the design and was not run. We ran no shared-softmax counterpart that combines or merges the deltas (as EASE and InfLoRA do); our CL-LoRA port shares one adapter across sessions.

\section{Limitations and conclusion}
\label{sec:limitations}
\label{sec:conclusion}
\paragraph{Limitations.} The study covers three English datasets with test sets of $50$ to $347$ documents and four encoder-only backbones; the ladder, SBR and SBR-Recall are evaluated on LayoutLMv3 and on one class-incremental partition of CORD. The freezing experiment, the memory-content ladder, the relabelled memory (\nOracleN{} so far) and SBR-Recall on Mixed are single- or few-seed diagnostics. Comparators from this literature that we did not run: a faithful ICE-O (frozen encoder, one head per session, constant Other logit), SBR with a constant background, a separated softmax with one shared background, per-class sigmoid heads (SSUL, SpanKL), MiB's distillation, PLOP and BPF; the MiB-style loss of \cref{sec:h2} is the background-shift correction we run on the same memory. Joint training is a reference, not a bound. SBR-Recall grows by one delta and one pass per session and freezes its base after session~1, so it may depend on the session order. SBR's rule reads each session's schema at training time. CoLaR's memory grows with the sessions, and storing no raw pixels or token ids is weaker than privacy.

\paragraph{Conclusion.} Replay retains documents under domain shift and fails under label growth because two things go wrong, and a memory repairs only one. Drift is answered by a whole-document memory. The background conflict is not: stale stored labels are part of it, and relabelling the older stored documents with their true labels leaves a shared softmax below joint training and below CoLaR-SBR (\nOracleN). It is answered at the readout, by letting an ``O'' label count only against the classes its annotator could see, and where label growth supplies the routing key that readout lets per-session deltas replace the memory. Continual document methods should be tested on a growing label space, with a mask-free metric, against a memory whose stale labels are refreshed.
