\begin{abstract}
Replaying a few hundred stored documents comes close to joint training on average when a continual key-information extractor meets new domains, yet fails when its label space grows. We ask why, as an investigation rather than a method. On a class-incremental stream of receipts we test a ladder of hypotheses, each with its prediction stated in advance, and measure where the errors go. Forgetting is not simply harder: with a whole-document memory and a shared softmax the model barely learns the last sessions it is trained on, which naive training learns well. Stale stored labels suffice to explain nearly all of it: giving every stored document its true labels before each session, an oracle no continual learner has, brings the same shared softmax to within $\nOraclePreJointGap$ points of joint training on every seed ($\nOraclePreFull$ against $\nJointFull$ full-label F1), although the current documents still call old entities ``O''. Without true labels, an unbiased loss in the style of MiB recovers about half of the full-label gap, while stopping the sharing of the background class closes most of it, as existing per-session readouts do: with the same memory, one background logit per session reaches $\nSbrFull$ full-label F1. The principle, familiar from training on partially annotated data, is that an ``O'' label is evidence only against the classes its annotator could see. Where label growth supplies the routing key, on a single-schema stream, per-session low-rank trunk updates can replace the memory; across schemas they did not, in one run.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Key-information extraction (KIE) labels each OCR token of a visually-rich document (form, invoice, receipt), using its words, its 2-D layout and the page image; multimodal encoders such as LayoutLMv3~\citep{huang2022layoutlmv3}, LiLT~\citep{wang2022lilt} and BROS~\citep{hong2022bros} define the state of the art. Deployed extractors meet new document types and growing schemas, while retraining on all history is blocked by cost and by privacy constraints: a continual-learning (CL) problem, whose central obstacle is catastrophic forgetting~\citep{mccloskey1989catastrophic}.

Replay is empirically the strongest remedy in the CL toolbox~\citep{masana2022class,wang2024survey}, and on documents it looks sufficient. On LayoutLMv3, a stream of forms and receipts under one fixed label space is learned by plain replay (ER) with $200$ stored documents to $\nErDil$ AA, within $\nErDilGapMax$ points of joint training on every seed (mean $\nJointDil$; \cref{app:drift}). Let the label space grow instead, by adding CORD's $30$ receipt fields six at a time, and the same method ($\nErCilBuf$ documents) reaches $\nEr$ AA, against $\nJoint$; both ER cells are legacy-protocol runs ($\dagger$) that early-stop on the test split, which favours ER (\cref{sec:setup}). Distillation, prompts, low-rank adapters and the continual-NER methods built for the shift of the ``O'' label do no better (\cref{tab:main}). A class-incremental stream is expected to be harder; what is not obvious is why a memory that holds the old documents does not help. This paper is about that question: \emph{why does replay, which solves domain shift, fail when the label space grows?}

\input{fig/conflict}

We treat it as an investigation (\cref{tab:ladder}): we write down the explanations a reader would offer, state what each predicts before its test, test each with an intervention on the same encoder, stream and recipe, and measure where the final model's errors go (\cref{fig:findings}). Forgetting is not just harder (H0): with a whole-document memory that retains under domain shift, the model suppresses the last sessions it is trained on, which naive training does not do. Stale labels in the memory (H1) suffice to explain nearly all of the failure: relabelling the older stored documents at each boundary recovers much of the gap, and relabelling every stored document before each session, an oracle, brings the shared softmax to within $\nOraclePreJointGap$ points of joint training on every seed, although the current documents still call old entities ``O'' (H2). Without true labels, a MiB-style unbiased loss recovers about half of the full-label gap, and removing the shared background (H3, \cref{fig:conflict}) closes most of it, given a memory; then per-session isolation can replace the memory (H4), but only where label growth supplies a routing key.

None of the ingredients is new. The background shift is known from class-incremental segmentation~\citep{cermelli2020mib,douillard2021plop,cha2021ssul}, from incremental detection, where both its stored side~\citep{liu2023abr} and its two-sided form~\citep{mo2024bpf} have been named, and from continual NER~\citep{monaikul2021extendner,zhang2023cpfd,ma2023learning}; separated softmaxes~\citep{ahn2021ssil}, per-task heads with a ``none of mine'' output~\citep{kim2022more} and per-session softmaxes over a constant Other logit~\citep{liu2023ice} already undo the shared normalisation. What has not been done is to take apart, on token-labelled documents, why replay fails: which part a memory repairs, which part survives a memory with true labels, and what the errors of each look like.

\paragraph{Contributions.}
\begin{enumerate}
  \item \textbf{The investigation.} A decomposition of why replay fails under label growth that prior work did not run on token-labelled documents: a memory $\times$ readout factorial, the stored-label side isolated by relabelled memories, of which the one that is never stale closes the gap under a shared softmax to within $\nOraclePreJointGap$ points of joint training (an oracle), and measurements of where the errors go under each readout (\cref{sec:investigation}): with a shared softmax and a memory the current session is suppressed; with a blocked readout and no memory, drift sends old entities to another session's class through over-claiming blocks.
  \item \textbf{An empirical finding, not a new mechanism.} A per-session background readout, as in ICE-O and MORE, combined with whole-document replay and a supervision rule in the spirit of training on disjoint tag sets, closes most of the gap to joint training in continual KIE on every seed, where the continual-NER and replay methods in our comparison do not. Our instantiation (SBR) differs from ICE-O in a learned background per session and in old blocks kept trainable from the memory (\cref{sec:design}).
  \item \textbf{Boundary conditions.} With the conflict removed, per-session low-rank trunk deltas (SBR-Recall) replace the memory on a single-schema stream, within $\nRecallJointGap$ points of joint training on every seed under both metrics, and fail without a memory across annotation schemas (one seed), where the task-identity view says they must (\cref{sec:recall}); on images, which have no background class, the latent memory is competitive with raw replay while SLCA and RanPAC lead (\cref{app:image}).
\end{enumerate}

\section{Related Work}
\label{sec:related}
\paragraph{Background shift.} When each step annotates only its own classes, the background label changes meaning. In class-incremental segmentation MiB~\citep{cermelli2020mib} matches a background label with the probability of background or any old class in the loss, and the old model's background with background or any new class in the distillation; PLOP~\citep{douillard2021plop} and SSUL~\citep{cha2021ssul} pseudo-label the background with the old model. Incremental detection has named both its stored side~\citep{liu2023abr} and its two-sided form~\citep{mo2024bpf}. In continual NER the shift of ``O'' is the unlabelled-entity problem~\citep{ma2023learning}, answered by distillation on ``O'' tokens~\citep{monaikul2021extendner} and pseudo-labels~\citep{zhang2023cpfd}. We do not claim the conflict; we separate its stored and current sides with relabelled memories and an unbiased loss and measure what each leaves.

\paragraph{Separated readouts and task identity.} A softmax over old and new classes together biases them, and separating it removes the bias~\citep{ahn2021ssil}; ER-ACE~\citep{caccia2022erace} masks the old classes out of the softmax of incoming samples only. Giving each task its own ``none of mine'' output turns class-incremental learning into within-task prediction plus task identification~\citep{kim2022theoretical}: MORE~\citep{kim2022more} isolates each task's parameters on a frozen pre-trained transformer, trains a head per task whose out-of-distribution output learns from saved samples, and lets the most confident head answer; in class-incremental extraction ICE-O~\citep{liu2023ice} trains, on a frozen encoder and with no memory, one softmax per session over a constant Other logit and that session's types, so that a mention is Other only if every session scores below that logit. SBR is this pattern on documents with a learned background per session and old blocks kept trainable from a memory. SBR-Recall shares MORE's isolation, with per-session low-rank trunk deltas, but trains each block's ``none of mine'' logit on its own session's negatives, with no saved samples.

\paragraph{Continual document IE.} Document-level continual learning is recent and small: multimodal LLMs forget under fine-tuning~\citep{zhai2023investigating}, and GDI-Bench~\citep{gdibench} limits it by freezing most parameters; continual table detection~\citep{minouei2022table} uses plain ER; ProtoNER~\citep{kumar2023protoner} adds key-information classes from a few documents with prototypes; AMD-Proj~\citep{sassioui2026amdproj} projects gradients against a memory of task subspaces; and \citet{sassioui2026documents} benchmark layout-aware models by stream regime, finding that no method they test consistently preserves old knowledge under label-space shift and that, for the non-replay methods they test, domain transfer forgets most. They decompose forgetting by regime of the stream; we decompose it by cause, within label growth. Our memory is a form of latent replay~\citep{hayes2020remind,pellegrini2020latent} that keeps whole documents; the broader CL families are surveyed by \citet{wang2024survey}.

\section{Setup}
\label{sec:setup}
\paragraph{Streams and models.} A document is a triple of OCR tokens, normalised boxes and the page image; the model emits BIO tags per token, scored by entity-level F1 (\texttt{seqeval}). \textbf{CIL-CORD}, the stream of every rung: CORD's $30$ receipt classes arrive six at a time over five sessions; the head grows, and every entity outside the session, earlier or later, is labelled ``O''. \textbf{DIL}: FUNSD$\rightarrow$SROIE$\rightarrow$CORD under one fixed four-entity schema. \textbf{Mixed}: six sessions over three datasets and annotation schemas. LayoutLMv3-base~\citep{huang2022layoutlmv3} is the encoder of every rung; LiLT~\citep{wang2022lilt}, BROS~\citep{hong2022bros} and text-only BERT appear on DIL. Heads are linear. \Cref{tab:bench} summarises the streams; \cref{app:setup} gives their sessions.

\paragraph{Memory and comparison set.} Every memory-based rung uses one whole-document latent memory (CoLaR, \cref{sec:memory}): $50$ documents per session stored as rank-$128$ SVDs of their layer-$4$ activations, replayed through the upper layers. The comparison set holds naive fine-tuning and joint training as references and eight methods from five families (\cref{tab:main}): ER~\citep{rolnick2019er}, DER++~\citep{buzzega2020der}, LwF~\citep{li2017lwf}, CODA-Prompt~\citep{smith2023coda}, CL-LoRA~\citep{he2025cllora}, LCA~\citep{lca2026}, and the continual-NER methods CPFD~\citep{zhang2023cpfd} and IS3~\citep{qiu2024is3}; \cref{app:baselines} gives our ports and protocols.

\paragraph{Protocol.} AdamW, learning rate $5{\times}10^{-5}$ (LCA keeps its own SGD recipe; \cref{app:baselines}), batch size $2$, seeds 42, 7 and 123. Under the \emph{clean protocol} every session trains in full precision for at most $10$ epochs (joint training: $100$) and early-stops on $10\%$ held out from its \emph{training} data; the test split never selects a model. Cells marked $\dagger$ come from earlier runs (\emph{legacy protocol}) that early-stop on the test split and vary in epoch cap and precision. A cell is clean only when all three clean seeds exist (\cref{app:setup}).

\paragraph{Scoring.} The headline number is the \emph{full-label F1}: the final model on the complete CORD test set with all 30 classes, as in continual NER~\citep{ma2023learning}. Only clean runs record it; against a cell with only AA ($\dagger$, DIL, Mixed) we compare in AA. Retention needs per-session test splits, whose labels show only that session's classes; from $R[i,j]$, the F1 on session $j$ after session $i$, AA $=\tfrac1T\sum_j R[T,j]$. Scored raw, such labels charge a model for every correct entity of another session, and penalise it for knowing more classes (\cref{app:setup}); we score each session \emph{session-restricted}, mapping a predicted tag outside session $j$'s label set to ``O'' before span matching. AA averages the sessions, while session~1 holds $\mSessOneShare\%$ of the $\mTestSpans$ test spans; on every seed both metrics order the main groups of clean runs the same way (\cref{app:setup}). Tuning and evaluating on the same scenario overstates CL methods~\citep{cha2025hyperparameters}. The comparison set was fixed after a first grid on all three streams, the memory settings were chosen on DIL and carried unchanged, SBR's claim threshold ($0.5$) was not tuned, and the one setting chosen on CIL-CORD is SBR-Recall's delta capacity; \cref{app:baselines,app:results} give the detail, including the methods dropped.

\subsection{H0: is it just harder forgetting?}
\label{sec:h0}
\paragraph{Prediction.} If label growth only made drift harder, the memory that retains under domain shift would still retain here, a raw memory would do better, and the losses would look like naive forgetting, where old sessions are lost and the newest is learned well.

\paragraph{Test and result: refuted.} The CoLaR memory comes within $\nColarDilGapMax$ AA points of joint training on DIL on every seed (means $\nColarDil^\dagger$ against $\nJointDil^\dagger$). On CIL-CORD with a shared softmax it reaches $\vColarFull$ full-label F1 ($\vColar$ AA) against $\vJointFull$ ($\vJoint$). Raw documents do no better (ER, $\nEr$ AA$^\dagger$, below every CoLaR seed), but ER also trains every layer, keeps $200$ documents and is a legacy run, so this row does not isolate memory fidelity. What separates the memory run from naive forgetting is the session being trained: its newest session ends at $\mColarLastMin$ to $\mColarLastMax$ F1, whereas naive training learns every session to at least $\nNaiveDiagMin$ on every seed. The memory run also freezes layers $1..4$ after the first session and replays four stored documents per step; with the same freezing (and, with the memory, the same replay), the blocked readouts with and without the memory learn every session to at least $\nSbrDiagMin$ (per-seed minimum; mean in \cref{fig:heatmaps}), so lost plasticity does not explain the suppression. It also keeps $\mColarRMin$ to $\mColarRMax\%$ of the old sessions' spans where naive training keeps none, at an old-span precision of at least $\mColarOldPLb\%$ (a lower bound; \cref{app:setup}).

\paragraph{What it rules out, and what it leaves.} Drift alone does not explain the failure: the memory that answers drift on DIL leaves the session being trained suppressed here, which naive training, with all of its drift, does not show. Drift is still real: naive training keeps nothing of the old sessions; on a fixed label space every encoder forgets its earlier domains and replay repairs it where EWC and LwF do not, and under naive fine-tuning the representation drifts most near the output on all four encoders, as known for image classifiers~\citep{ramasesh2021anatomy} (\cref{app:drift}).

\subsection{H1: are the stored labels stale?}
\label{sec:h1}
\paragraph{Prediction.} A document stored at session $t$ carries ``O'' on every entity of another session, earlier or later, so the memory itself calls background what the model must keep or learn. In detection the same staleness of replayed examples was named foreground shift and blamed for replay's failure~\citep{liu2023abr}. If these stale labels are the cause, giving the stored documents their true labels should close the gap with the shared softmax unchanged.

\paragraph{Test.} We refresh the stored labels at two points. \emph{At each boundary}, every document stored \emph{before} the session just finished receives the true labels of all classes seen so far; that session's own documents keep their labels until the next boundary, and no such refresh covers the session trained next. It rewrites $\nOracleRelabelTrain$ stale tokens before sessions 3 to 5 (and $\nOracleRelabelAfter$ after the last session, which changes no training; seed 42). \emph{Before each session}, every stored document receives the true labels of all classes in the head as grown for that session, so no stored label is stale while a session trains; the current documents still call old entities ``O''. Both read labels no continual learner has and are diagnostics, not methods.

\paragraph{Result: partly at the boundary, supported before each session.} At the boundary, against the same memory without the refresh, it lifts full-label F1 from $\nColarSeedFull$ to $\nOracleFull$ and AA from $\nColarSeed$ to $\nOracle$ (means, \nOracleScope): \nOracleShareFull\% and \nOracleShare\% of the seed-matched gap to joint training ($\nJointSeedFull$, $\nJointSeed$), and still below CoLaR-SBR ($\nSbrSeedFull$, $\nSbrSeed$) under both metrics. What it cannot reach is the session being trained, whose classes are ``O'' in every stored document: sessions 3 to 5 are learned only to $\nOracleLateMin$ to $\nOracleLateMax$ F1 on their own diagonal, sessions 3 and 4 rise to $\nOracleNextMin$ to $\nOracleNextMax$ one session later, and the last ends at \nOracleLast, a fifth of AA but $\nOracleLastShare\%$ of the test spans. Refreshed before each session, the same memory with the same shared softmax reaches $\vOraclePreFull$ full-label F1 and $\vOraclePre$ AA, within $\nOraclePreJointGap$ points of joint training on every seed under both metrics and above CoLaR-SBR on every seed (\cref{tab:ablation}).

\paragraph{What it rules out.} Stale stored labels suffice to explain nearly all of the failure of replay under a shared softmax, on the session being trained as much as on old ones (\nOracleN). The control is an oracle: it shows what the memory must hold, not how a continual learner could obtain it.

\subsection{H2: do current documents mislabel old entities?}
\label{sec:h2}
\paragraph{Prediction.} A current document labels every entity of an earlier session ``O'', so even a memory with true labels is opposed in every batch by documents that call the same strings background. This is the second side of the conflict named in detection~\citep{mo2024bpf}. If this pull is the cause, a loss that lets a current ``O'' mean ``O or an earlier class'', as MiB does for segmentation~\citep{cermelli2020mib} and marginal-likelihood taggers do offline~\citep{greenberg2018marginal}, should close the gap within a shared softmax.

\paragraph{Test.} Two clean controls test it. The never-stale memory of H1 changes only the stored side and leaves every current document stale. The second keeps the memory and the shared softmax, uses no true labels, and replaces the cross-entropy with MiB's unbiased form in both directions: a current ``O'' token matches ``O'' or any earlier-session class, a replayed one ``O'' or any class introduced after storage (no distillation).

\paragraph{Result: not needed, and a loss repair only partly helps.} With true stored labels the gap closes although every current document still calls old entities ``O'' (H1), so the current side is not needed to explain the failure. The MiB-style loss lifts full-label F1 to $\vMibFull$ and AA to $\vMib$, above CoLaR and below joint training on every seed under both metrics: $\nMibShareFull\%$ of the seed-matched gap in full-label F1 and $\nMibShare\%$ in AA, and below CoLaR-SBR on every seed. It learns every session to at least $\nMibDiagMin$ on its diagonal, so it removes the suppression of the session being trained, but the first session ends at no more than $\nMibFirstMax$ F1 on any seed. Restricting both losses to their classes instead (ER-ACE's asymmetric cross-entropy~\citep{caccia2022erace} on current ``O'' tokens; legacy runs$^\dagger$) averages $\nSlicedBoth$ AA over three seeds (\cref{fig:findings}a).

\subsection{H3: is it the shared normalisation?}
\label{sec:h3}
\paragraph{Prediction.} If the conflict lives in the shared normalisation, one background logit trained by documents that disagree about what is background, then one background logit per session, normalised with that session's tags only, should close most of the gap with no true labels. This is SS-IL's diagnosis of a shared softmax~\citep{ahn2021ssil} with a background added, and ICE-O's readout~\citep{liu2023ice} without its frozen encoder. It needs the memory: separating the labels does not undo drift, so without a memory the same readout should fail, and fail the way drift does.

\paragraph{Result: supported, on every seed.} With the memory the session-blocked readout (CoLaR-SBR, \cref{sec:sbr}) reaches $\vSbrFull$ full-label F1 and $\vSbr$ AA, $\nSbrGapFullMin$ to $\nSbrGapFullMax$ full-label points below joint training per seed, above the memory relabelled at each boundary and below the memory relabelled before each session on every seed, under both metrics. The owning block claims $\mSbrOwnerMin$ to $\mSbrOwnerMax\%$ of the old entity tokens, and most remaining errors ($\mSbrSameMin$ to $\mSbrSameMax\%$ of the wrong tokens) give the token another tag of its own session, a B/I swap of the right type included. Without the memory the same readout scores $\vNoBankFull$ ($\vNoBank$ AA), and its errors go elsewhere: not one old entity token is predicted ``O'', $\mNoBankOtherMin$ to $\mNoBankOtherMax\%$ of the wrong ones receive another session's class, and each old block claims $\mNoBankFalseMin$ to $\mNoBankFalseMax\%$ of the tokens of its own split that are not its entities, against $\mSbrFalseMin$ to $\mSbrFalseMax\%$ with the memory. Old blocks on a drifted trunk claim far more than their own entities; that is drift, and the memory reduces it.

\paragraph{What goes against it.} It is neither the only repair nor the best one: true stored labels bring a shared softmax closer to joint training, above CoLaR-SBR on every seed; the blocked readout needs no true label. The readout does nothing alone, and it is not free: on DIL, where there is nothing to separate, CoLaR-SBR is below CoLaR (AA $\nSbrDil^\dagger$ against $\nColarDil^\dagger$).

\paragraph{What discriminates what.} Drift (H0) is told apart from the label hypotheses (H1 to H3) by the session being trained, suppressed under a shared softmax with a memory and learned without one, and by the same memory coming within $\nSbrGapFullMax$ full-label points of joint training on every seed once its labels are true or its background is not shared. Within the label hypotheses, the never-stale memory (an oracle) decides: with true stored labels and stale current documents a shared softmax comes within $\nOraclePreJointGap$ points of joint training, so the stored side (H1) suffices to explain nearly all of the failure and the current side (H2) is not needed. We read the shared normalisation (H3) as the channel through which stale labels act, as negatives for every class; the blocked readout closes most of the gap without true labels, and the constant-background control (queued) tests this reading.

\section{From diagnosis to design}
\label{sec:design}
\paragraph{The principle.} The rungs point at one fact about annotation under label growth, familiar from training on partially annotated data~\citep{greenberg2018marginal}. A token marked ``O'' in session $s$ means ``none of the classes annotated in session $s$'': it is evidence against those classes and silent about every other. A shared softmax turns it into evidence against all classes at once (H3), and stale stored labels are the same error made by the memory (H1). The principle: \emph{supervise each class only with negatives from documents that annotated it, and normalise together only classes that were annotated together.} Three consequences follow: each session needs its own background; the memory must keep whole documents with their own labels and the session that wrote them; and each session's background logit, trained on that session's true negatives, is also a detector of its entities, so it can route a token without task identity.

\subsection{SBR: one background per session}
\label{sec:sbr}
SBR is our instantiation of a per-session background readout~\citep{liu2023ice,kim2022more}. Every session that brings new tags opens a block $b$ holding those tags $\mathcal{T}_b$. A shared softmax normalises over $\{\mathrm{O}\}\cup\bigcup_b\mathcal{T}_b$. SBR gives every session its own background logit $o_b(x)=w_b^{\top}h(x)+c_b$ on the token feature $h(x)$ and normalises each block separately:
\begin{equation}
p_b(\cdot\mid x)=\operatorname{softmax}\big([\,o_b(x),\,z_{\mathcal{T}_b}(x)\,]\big),
\label{eq:block}
\end{equation}
where $z(x)$ are the tag logits of the usual linear head and $z_{\mathcal{T}_b}(x)$ its entries for the tags in $\mathcal{T}_b$. Within block $b$ a token labelled ``O'' in session-$b$ data is truly background, so the block's supervision is never stale. For a token $x$ with label $y$ in a document of session $s$,
\begin{equation}
\begin{gathered}
\mathcal{L}(x,y,s)=\sum_{b}\,m_{sb}\;\mathrm{CE}\big(p_b(\cdot\mid x),\,y_b\big),\\
y_b=\begin{cases} y & y\in\mathcal{T}_b\\ \mathrm{O}_b & \text{otherwise,}\end{cases}
\end{gathered}
\label{eq:sbr}
\end{equation}
with one rule for the mask: $m_{sb}{=}1$ when session $s$ annotates every tag of $\mathcal{T}_b$; $m_{sb}{=}1$ with $y_b{=}\mathrm{O}_b$ when $b$ belongs to a different annotation schema (the document is annotated under its own schema, so every token is a negative for $b$; a training-time convention that, between related schemas such as SROIE and CORD, can call a real entity background); and $m_{sb}{=}0$ otherwise, because the document's ``O'' labels say nothing about block $b$. Stored documents follow the rule of the session that stored them. A session that adds no tags creates no block, so on a fixed label space SBR has a single block. At inference each block reports its claim $e_b=1-p_b(\mathrm{O}_b\mid x)$; the block with the largest $e_b$ labels the token with its best tag if $e_b>0.5$, and the token is ``O'' otherwise, as in ICE-O's ``Other unless some session scores above it''. Blocks trained at different times need not produce claims on one scale, which is why we measure the routing directly (\cref{fig:findings}b). \Cref{fig:method} draws both readouts; \cref{app:method} gives the supervision modes and the memory accounting.

\subsection{The memory}
\label{sec:memory}
SBR's supervision needs stored documents that keep each token's label at its position and the session that wrote it. CoLaR (Compressed Latent Replay) keeps whole documents: after the first session layers $1..k$ are frozen, and each stored document's layer-$k$ activations $H_j$ are kept as a rank-$r$ truncated SVD with its boxes, mask, labels and session, rebuilt at replay and injected at layer $k$. On DIL it retains $\vColarDil^\dagger$ AA in $60$\,MB, against $\vErDil^\dagger$ for ER with $200$ raw documents; it holds no raw pixels or token ids (no privacy claim: activations can leak content).

\subsection{SBR-Recall: the test of H4}
\label{sec:recall}
\paragraph{Prediction (H4).} With the conflict removed, the memory is needed only against drift, and the task-identity view~\citep{kim2022theoretical} says when it can go: if each block is read under the trunk state that learned it, nothing drifts for that block, provided the model can tell which state a token belongs to. On one schema under label growth each block's background logit supplies that key. Across schemas the all-background terms of \cref{eq:sbr} train every old block towards background on other-schema documents with nothing to pull it back, so isolation should fail without stored documents; on a fixed label space there is one block and nothing to route by.

\paragraph{The intervention.} SBR-Recall stores, for each session $b>1$, a low-rank delta $\Delta_b$~\citep{hu2022lora} of the layers above $k$ (rank $64$ on the attention projections and feed-forward layers), freezes these layers after the first session (the base $\theta_0$; $\Delta_1{=}0$), and computes block $b$ under the trunk state that learned it:
\begin{equation}
p_b(\cdot\mid x)=\operatorname{softmax}\big([\,o_b,\,z_{\mathcal{T}_b}\,]\big)\big(x;\,\theta_0+\Delta_b\big).
\label{eq:recall}
\end{equation}
Every term of \cref{eq:sbr} is computed under the delta its block is read under, at training and test time. Without a memory on a single-schema stream no term of a later session involves an old block, so each old block's $e_b$ is unchanged up to weight decay, and only competition from new blocks can move its tokens (\cref{app:method}).

\paragraph{Result: supported, with its predicted failure.} On CIL-CORD SBR-Recall reaches $\vRecallFull$ full-label F1 ($\vRecall$ AA) with no stored document, within $\nRecallJointGap$ points of joint training on every seed under both metrics; its owning block claims $\mRecallOwnerMin$ to $\mRecallOwnerMax\%$ of the old entity tokens. Our port of ICE-O (frozen encoder, one head per session over a constant Other logit, no memory; our clean recipe) forgets nothing (its final row is within $\nIceODevMax$ points of its diagonal on every seed) and reaches $\vIceOFull$ full-label F1 ($\vIceO$ AA), below SBR-Recall on every seed under both metrics; under our $10$-epoch cap sessions 4 and 5 were still improving when training stopped and session~3 early-stopped at $\nIceOThirdMax$ F1, on every seed, so this is a lower bound for ICE-O, not its published accuracy. On Mixed without a memory it scores $\nRecallMixNoMem$ AA$^\dagger$ (seed 42): the blocks of the other schemas fall silent until their domain returns, as predicted, and with the $50$-document memory restored it scores $\nRecallMixMem$ (\cref{app:results}). On a fixed label space SBR-Recall has a single block; that it cannot replace the memory there follows from the design and was not run.

\section{Limitations and conclusion}
\label{sec:limitations}
\label{sec:conclusion}
\paragraph{Limitations.} The study covers three English datasets with test sets of $50$ to $347$ documents and four encoder-only backbones; the ladder, SBR and SBR-Recall are evaluated on LayoutLMv3 and on one class-incremental partition of CORD. SBR-Recall on Mixed, the design-choice ablations and the image probe are single- or few-seed diagnostics. We did not run several comparators from this literature (among them PLOP, BPF, MiB's distillation and per-class sigmoid heads); of MiB we ran only the unbiased loss (\cref{sec:h2}). Joint training is a reference, not a bound. ICE-O ran under our recipe and was still improving at the epoch cap. SBR-Recall grows by one delta and one pass per session and freezes its base after session~1, so it may depend on the session order. CoLaR's memory grows with the sessions, and storing no raw pixels or token ids is weaker than privacy.

\paragraph{Conclusion.} Replay retains documents under domain shift and fails under label growth because two things go wrong, and a memory repairs only one. The background conflict is not: the stored labels go stale, and that suffices to explain nearly all of the failure, since an oracle that gives every stored document its true labels before each session brings a shared softmax to within $\nOraclePreJointGap$ points of joint training on every seed. Without true labels, a MiB-style loss recovers about half of the full-label gap. Most of the conflict is removed at the readout, by letting an ``O'' label count only against the classes its annotator could see; where label growth supplies a routing key, per-session deltas then replace the memory. Continual document methods should be tested on a growing label space, with a mask-free metric.
