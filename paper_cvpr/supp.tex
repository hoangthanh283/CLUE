\section{Setup details}
\label{app:setup}

\paragraph{Datasets.} FUNSD (\texttt{nielsr/funsd-layoutlmv3}; 149/50 train/test forms), CORD (\texttt{naver-clova-ix/cord-v2}; 800/100/100 receipts), SROIE (\texttt{mp-02/sroie}; 626/347 receipts). We use the dataset-provided OCR and boxes throughout, page images at 224$\times$224 and a text length of 512 tokens; with the 197 image tokens of LayoutLMv3 a document is a sequence of 709 positions.

\paragraph{CIL-CORD.} CORD's 30 fine-grained classes (61 BIO tags with ``O'') arrive in five sessions of six classes (\cref{tab:cilsessions}). A session's training and test pools keep every receipt that contains at least one of that session's entities, and every token of a class outside the session is labelled ``O''. The head grows by twelve tags per session. Joint training uses the full-label pool (each receipt once, with all its labels) rather than the concatenation of the masked per-session copies, which would feed contradictory labels for the same document. Class imbalance across sessions is left as it is.

\paragraph{DIL unified schema.} A single four-entity label space \{HEADER, KEY, VALUE, OTHER\} (9 BIO tags) is held fixed over FUNSD$\rightarrow$SROIE$\rightarrow$CORD. FUNSD: HEADER$\rightarrow$HEADER, QUESTION$\rightarrow$KEY, ANSWER$\rightarrow$VALUE. SROIE: COMPANY$\rightarrow$KEY; ADDRESS/DATE/TOTAL$\rightarrow$VALUE. CORD: menu/sub\_total/total$\rightarrow$VALUE; void\_menu/sub$\rightarrow$OTHER. KEY originates only from FUNSD and SROIE, so the schema is VALUE-dominant; we report per-class F1 for every DIL result and treat a high aggregate as retention only if the sparse classes are retained. The reverse order is used as a robustness check.

\paragraph{Backbones.} LayoutLMv3-base is the primary encoder (text, layout and image patches in one sequence). LiLT and BROS are text-and-layout encoders and BERT-base is text only; all four have twelve layers of width 768. Every head is a single linear layer: an MLP head with ten or more labels saturates and collapses to all-background after class-incremental expansion. When the head grows, old rows are kept and new rows are drawn from $\mathcal{N}(0,0.02^2)$.

\paragraph{The clean protocol in full.} Every clean run uses fp32, batch size $2$ with gradient checkpointing, AdamW with learning rate $5{\times}10^{-5}$, weight decay $0.01$ and gradient clipping $1.0$. Each session trains for at most $10$ epochs ($100$ for joint training) and stops early when the F1 on a held-out split has not improved by $0.1$ points for $2$ epochs, after which the best weights are restored. The held-out split is $10\%$ of that session's \emph{training} pool, drawn with a generator seeded by the run seed plus the session index (the run seed for joint training); the test split is never used for model selection. Class-incremental sessions are scored with session-restricted scoring (\cref{app:scoring}); on CIL-CORD the final model is also scored on the unmasked test set (full-label F1). Mixed and DIL have no full-label set, so the column is CIL-CORD only. Seeds are 42, 7 and 123. CoLaR-family runs use $k{=}4$, rank $r{=}128$, $50$ stored documents per session and $4$ replayed documents per step; the clean ER row keeps $250$ raw documents, as many as CoLaR stores on CIL-CORD. A table cell switches to the clean protocol only when all three clean seeds exist, so no cell mixes the protocols.

\paragraph{Compute.} The runs reported here ran on a single 6\,GB GPU, except some first-grid rows (\cref{app:repro}). Per-run times of the headline cells are in \cref{tab:perseed} and \cref{app:repro}.

\section{Scoring, explained}
\label{app:scoring}

\paragraph{Definitions.} Let $\mathcal{A}_j$ be the tags of session $j$ and $\mathcal{D}_j$ its test documents, whose gold labels show only $\mathcal{A}_j$ (every other entity is ``O''). All three scores are entity-level F1 from \texttt{seqeval}.
\begin{itemize}\setlength\itemsep{1pt}
\item \emph{Legacy scoring} compares the model's raw predictions on $\mathcal{D}_j$ with the masked gold labels.
\item \emph{Session-restricted scoring} first maps every predicted tag outside $\mathcal{A}_j$ to ``O'' and then compares. It does not re-take the argmax among the tags of $\mathcal{A}_j$: a token whose best tag belongs to another session becomes ``O'', never its second-best in-session tag. For SBR the mapping is applied after the block decision of \cref{eq:infer}.
\item \emph{Full-label F1} scores the final model, with no mapping, on the unmasked CORD test set (all $100$ receipts, all $30$ classes).
\end{itemize}

\paragraph{A worked example.} Take one receipt with a menu item name (class \texttt{menu.nm}, session~1) and the total price (\texttt{total.total\_price}, session~5), and a model that labels both correctly. In session~1's test labels the total price is ``O'', so under legacy scoring the correct total-price span is a false positive there: precision $1/2$, recall $1$, F1 $0.67$ for session~1 on this receipt. Symmetrically, the correct menu-name span is a false positive in session~5. A perfect model is charged once in every session that does not own a predicted entity, so legacy scoring penalises the model for knowing more classes, and the penalty grows with the number of sessions; this is why joint training, which labels every class, reads $33.3$ under legacy scoring on CIL-CORD (\cref{tab:grid}) and $\vJoint$ under restricted scoring. Under legacy scoring naive training, LwF, ER and DER++ sit at $16$--$19$ AA on average on CIL-CORD (\cref{tab:grid}), a band that could be read as a floor of the scenario; most of it is this artefact. Under session-restricted scoring the total-price prediction is mapped to ``O'' in session~1 and counts in session~5 only, so both sessions score $1$. If instead the model labels the total price as \texttt{menu.price} (a session-1 class), the predicted span is a false positive in session~1 and the gold total is a miss in session~5: one false positive and one false negative, exactly what ordinary entity F1 charges for a wrong type.

\paragraph{Why restricted scoring charges each error at most once.} Every predicted entity has one class, and that class belongs to exactly one session; outside that session the mapping removes it, so it can be a false positive only in its owning session. Every gold entity appears unmasked only in the test labels of its own session, so it can be a false negative only there. A confusion between sessions therefore still costs a miss. The caveat is coverage: $\mathcal{D}_j$ keeps only receipts that contain an entity of session $j$, so a false positive of a session-$j$ class on a receipt without any session-$j$ entity is never counted. Full-label F1 has no such gap, which is why we report it.

\paragraph{Where the two metrics agree.} \cref{tab:agree} lists every clean-protocol run that records both numbers. On every seed both metrics order the same groups: naive training and no-memory SBR, then CoLaR with a shared softmax, then the true-label refresh, then CoLaR-SBR, SBR-Recall and joint training. Inside a group they can disagree on the order: naive training and no-memory SBR swap on two seeds, and so do runs of the top group that are within about a point of each other. For CoLaR-SBR, SBR-Recall and joint training the two metrics differ by at most $\nAgreeHighMax$ points on each seed, so for these runs the restricted AA of the main comparison (Tab.~3 of the main paper) is not inflated by the coverage gap. For weak models restricted AA is the more lenient of the two, by $\nAgreeLowMin$ to $\nAgreeLowMax$ points for the runs without a memory and $\nAgreeColarMin$ to $\nAgreeColarMax$ for CoLaR: no-memory SBR reads $\vNoBank$ AA against $\vNoBankFull$ full-label F1, because a session's test split keeps only receipts that contain its entities, so most of that model's false positives on other receipts go uncounted (the coverage caveat above). The true-label refresh is the exception in the other direction (full-label F1 above AA); \cref{app:conflict} explains it. The table is regenerated as clean runs complete.

\section{Method details}
\label{app:method}

\subsection{CoLaR}
\label{app:colar}
\paragraph{What is stored.} After the first session, the embeddings and layers $1..k$ are frozen; everything above, and the head, stays plastic. At the end of each session the hidden state entering layer $k{+}1$ is captured for $50$ training documents of that session (the first $50$ of the shuffled loader), from the same frozen layers that will produce it forever after, so a stored activation cannot go stale. Each document's activation matrix $H_j\in\mathbb{R}^{709\times768}$ is factorised by a truncated SVD and kept as $(U_r\Sigma_r)\in\mathbb{R}^{709\times r}$ and $V_r^{\top}\in\mathbb{R}^{r\times768}$ in fp16, together with the document's boxes, attention mask and labels (and, for SBR, the index of the session that stored it). No raw pixels and no token ids are kept.

\paragraph{Replay.} At every training step four stored documents are sampled uniformly, $\hat H_j=(U_r\Sigma_r)V_r^{\top}$ is rebuilt, and a forward pre-hook on layer $k{+}1$ replaces the hidden state of a dummy input by $\hat H_j$; the stored boxes and mask drive the layout position biases and the attention mask of the replayed pass. The loss is the cross-entropy of the current batch plus the cross-entropy of the replayed documents with their stored labels, with weight $1$. Gradient checkpointing is switched off for the replayed pass, because recomputation would re-run layer $k{+}1$ on the dummy input.

\paragraph{Memory accounting.} The method's memory is counted, per stored document, as the two fp16 factors, $2r(709{+}768)$ bytes ($378{,}112$ at $r{=}128$), and the boxes, mask and labels at the eight bytes per entry in which they are held ($24{,}576$ bytes); SBR adds one byte for the session index. A document therefore costs $402{,}689$ bytes in CoLaR-SBR, and the $250$ documents of CIL-CORD give the $100{,}672{,}250$ bytes recorded in every CoLaR-SBR run ($100.7$\,MB; $1$\,MB $=10^6$ bytes), against $272.3$\,MB for the same activations uncompressed (training log). These are the figures the paper reports. The implementation's stored record is about $1\%$ larger: on CIL-CORD and Mixed it also holds the document's labels in the \emph{final} label space ($4{,}096$ bytes), which include classes of sessions not yet seen and which a continual learner could not have, plus two small integer fields. No method in the paper reads this field; only the true-label refresh diagnostic of \cref{app:conflict} does, and a deployment would not store it. As held, a record is $406{,}800$ bytes against $402{,}689$ counted: $101.7$ against $100.7$\,MB for the $250$ documents of CIL-CORD and $122.0$ against $120.8$\,MB for the $300$ of Mixed. DIL is unaffected, and so is SBR-Recall without a memory, whose bytes are deltas.

\subsection{SBR}
\label{app:sbr}
\paragraph{Blocks.} A block is created by every session that introduces at least one tag not yet covered by a block; it holds those new tags $\mathcal{T}_b$, a background logit $o_b=w_b^{\top}h+c_b$ (a linear layer with bias from the 768-dimensional head input to one logit) and the schema of its session. A session that only re-annotates known tags (every DIL session after the first, the Mixed FUNSD revisit) creates no block, so on DIL SBR has exactly one block and differs from CoLaR only in its separate background logit and the thresholded decision. The tag logits $z$ are the rows of the one shared linear head.

\paragraph{The supervision rule.} For a document of session $s$ with tag set $\mathcal{A}_s$ and schema $d_s$, the supervision rule assigns every existing block $b$ one of three modes:
\begin{itemize}\setlength\itemsep{1pt}
\item \textbf{full} if $\mathcal{T}_b\subseteq\mathcal{A}_s$: session $s$ annotates every tag of the block, so its ``O'' labels are true negatives for that block; the target is $y$ for tags of $\mathcal{T}_b$ and $\mathrm{O}_b$ for every other token, including annotated entities of other blocks;
\item \textbf{all-background} if $d_b\neq d_s$: the block belongs to another annotation schema. The document is annotated under its own schema, so no token carries a tag of $b$, and every token's target is $\mathrm{O}_b$. This is a convention that uses each session's annotation schema at training time, not a fact about the document: across related schemas it can label a real entity of the other schema as background (SROIE and CORD are both receipt schemas and share entity kinds such as totals and dates), and Mixed is the scenario where this matters;
\item \textbf{skipped} otherwise: same schema, block not annotated, so the document's ``O'' says nothing about it.
\end{itemize}
A stored document is supervised by the plan of the session that stored it, evaluated over the blocks that exist when it is replayed. \cref{tab:plan} spells the plans out. On CIL-CORD every session has the same schema, so a document trains only its own block and the all-background mode never occurs. On Mixed the all-background mode is what keeps a block from claiming tokens of another dataset. An earlier version that created a block for every session and had no all-background mode failed on DIL exactly there: the SROIE session reached $23.6$ F1 on its own diagonal, because the FUNSD block, never trained on receipts, claimed receipt tokens (one seed, AA $66.5$).

\paragraph{Inference.} For each token every block reports $e_b=1-p_b(\mathrm{O}_b\mid x)$; the block with the largest $e_b$ labels the token with its most probable tag if $e_b>\tau$ ($\tau{=}0.5$), and the token is ``O'' otherwise (ties go to the lower block index):
\begin{equation}
\begin{gathered}
\hat y(x)=\begin{cases}\arg\max_{t\in\mathcal{T}_{b^\star}}p_{b^\star}(t\mid x) & e_{b^\star}>\tau,\\ \mathrm{O} & \text{otherwise,}\end{cases}\\
b^\star=\arg\max_b e_b.
\end{gathered}
\label{eq:infer}
\end{equation}
No task identity is used, and the session restriction of the evaluation is applied only after this decision.

\begin{algorithm}[t]
\caption{CoLaR-SBR: one session $s$ (tags $\mathcal{A}_s$, schema $d_s$)}
\label{alg:sbr}
\small
\begin{algorithmic}[1]
\State $\mathcal{N}\gets\mathcal{A}_s\setminus\bigcup_b\mathcal{T}_b$
\If{$\mathcal{N}\neq\emptyset$} add block $(\mathcal{T}=\mathcal{N},\,w,\,d_s)$ \EndIf
\State hold out $10\%$ of the session's training pool
\For{epoch $=1..10$, until early stopping}
  \For{each minibatch $X$ of session $s$}
    \State $\mathcal{L}\gets\sum_{(b,\text{mode})\in\mathrm{plan}(s)}\mathrm{CE}_b(X,\text{mode})$
    \State sample $4$ stored documents; rebuild $\hat H=(U_r\Sigma_r)V_r^{\top}$
    \State inject $\hat H$ at layer $k{+}1$; for each, add $\sum_{\mathrm{plan}(s')}\mathrm{CE}_b$ of its session $s'$ (mean over the four) to $\mathcal{L}$
    \State AdamW step on layers $k{+}1..12$ (session 1: all layers), head, all $w_b$
  \EndFor
\EndFor
\State restore the best weights; \textbf{if} $s=1$: freeze embeddings and layers $1..k$
\State store $50$ documents: $(U_r\Sigma_r,V_r^{\top})$, boxes, mask, labels, $s$
\end{algorithmic}
\end{algorithm}

\subsection{SBR-Recall}
\label{app:recall}
\paragraph{Deltas.} Every linear layer named query, key, value or dense in layers $k{+}1..12$ is wrapped by a module that holds one low-rank pair $(A_b,B_b)$ per delta and adds $\tfrac{\alpha}{r}\,xA_b^{\top}B_b^{\top}$ to the base output when delta $b$ is active. ``Dense'' covers the attention output projection and both feed-forward layers, so a layer carries six deltas and the eight layers above $k{=}4$ carry $48$. $A$ is initialised Kaiming-uniform and $B$ at zero, so a fresh delta is the identity. The headline setting is rank $64$, $\alpha{=}128$; the capacity ablation uses rank $8$, $\alpha{=}16$ on query, key and value only.

\paragraph{Which delta a session trains.} The first session trains the base network itself; afterwards the whole encoder is frozen ($\theta_0$) and only the head, the background weights and the current delta are trainable. A session that creates a block gets a fresh delta; a session that creates none reuses the delta of the first block it trains fully (on the Mixed revisit this is the base of the first session, so that session trains only the readout).

\paragraph{Losses under the delta a block is read under.} The loss groups the blocks of a document's plan by the delta each block is read under, runs one forward pass per distinct delta, and computes each block's term from the pass under its own delta. Frozen deltas add only the head to the autograd graph. Stored documents, when there is a memory, are grouped by session and pass through the layer-$k$ injection under each delta in the same way. An earlier implementation computed the all-background terms of other-schema blocks under the \emph{current} delta, which trained those blocks' readout on features from a trunk state they are never read under; its Mixed run (rank 64, seed 42) is an implementation error, not a result, and is not reported. CIL-CORD has a single schema, so its runs never contain such terms and are unaffected. \cref{alg:recall} summarises training and inference.

\paragraph{What ``cannot drift'' means.} Without a memory on a single-schema stream, a later session's loss contains only its own block, so an old block's base and delta are frozen, its background weights $w_b,c_b$ are outside the graph, and its rows of the shared tag head receive a zero gradient. Two effects remain. AdamW's decoupled weight decay still shrinks those rows, by under $1\%$ over a run ($5{\times}10^{-7}$ per step for at most ten epochs of four sessions). And each old block's $e_b$ is unchanged, but the arg-max over blocks is not: a new block can out-claim an old one on some tokens. In the legacy rank-64 runs this moves the final F1 of an old session by about a point in either direction (\cref{tab:delta}); in the clean rank-64 runs no session falls more than \nRecallMaxLoss\ points below its diagonal at any later boundary and none rises more than \nRecallMaxGain.

\paragraph{Inference and cost.} One forward pass per distinct delta produces the logits of the blocks read under it, and \cref{eq:infer} combines them. Our implementation repeats the full forward pass for each delta: five passes on CIL-CORD (base plus four deltas). Since the embeddings and layers $1..k$ are identical in all of them, a cached implementation repeats only the $12-k$ upper layers, $(k+5(12-k))/12\approx3.7$ encoder-layer equivalents of one forward pass at $k{=}4$, which is the figure in the main paper.

\paragraph{Parameters and memory.} A rank-64 delta has $8\times[3\cdot64\cdot(768{+}768)+64\cdot(768{+}768)+2\cdot64\cdot(768{+}3072)]=7{,}077{,}888$ parameters; We report the deltas at two bytes per parameter, that is, as if stored in half precision: the four deltas of CIL-CORD give $56{,}623{,}104$ bytes ($57$\,MB), as recorded in every rank-64 run. This is a reporting choice. The deltas were trained and evaluated in fp32 ($113$\,MB), and no run evaluated half-precision-rounded deltas. A rank-8 delta on query, key and value has $294{,}912$ parameters ($2.4$\,MB for four). With the $50$-document memory on Mixed the run records $177.4$\,MB counted, the deltas plus the CoLaR store ($178.7$\,MB as held).

\begin{algorithm}[t]
\caption{SBR-Recall: what changes relative to \cref{alg:sbr}}
\label{alg:recall}
\small
\begin{algorithmic}[1]
\If{$s=1$} train the base as in \cref{alg:sbr}; then freeze the encoder ($\theta_0$)
\ElsIf{session $s$ adds a block} create $\Delta_s$ ($B{=}0$); trainable: $\Delta_s$, head, $w_b$
\Else{} reuse the delta of the first block $s$ trains fully
\EndIf
\State \textbf{loss:} for each distinct delta $\Delta$ among the plan's blocks, forward $X$ under $\theta_0{+}\Delta$ and add the CE of every block read under $\Delta$
\State \textbf{inference:} forward under each distinct delta; block $b$ uses the pass under its own delta; decide by \cref{eq:infer}
\end{algorithmic}
\end{algorithm}

\subsection{SBR-Recall on the mixed stream}
\label{app:recallmix}
Three Mixed runs of SBR-Recall exist, all rank 64 and seed 42. The first computed the cross-schema terms under the wrong delta (\cref{app:recall}) and is not a result. The second is the corrected method without a memory; the third adds the $50$-document CoLaR memory. Their matrices are in \cref{tab:recallmix}.

\paragraph{Without a memory the blocks see-saw.} Read the no-memory matrix by columns. FUNSD sessions~1 and~2 are learned ($87.6$, $90.8$) and fall to $0.0$ as soon as SROIE arrives in session~3; SROIE is learned ($82.0$) and falls below $10$ when CORD arrives; both CORD sessions hold ($95.8$, $95.5$) until the FUNSD revisit, when FUNSD returns ($87.3$, $85.6$) and SROIE and the CORD blocks fall to $8.1$ or below. The mechanism is the all-background mode. On a current document of another schema every old block is trained towards $\mathrm{O}_b$ on every token, and without stored documents nothing trains it towards its own tags, so its background logit wins and the block stops claiming tokens. The trunk is frozen and the old deltas are not updated, so this is a readout effect, not drift: the readout rows and background weights of the old blocks are shared across deltas and are moved by these terms. When a block's own schema returns, it is supervised fully again and recovers within one session.

\paragraph{With the memory the see-saw disappears.} Stored documents supply the positive counterweight: in the with-memory matrix no column falls to zero, the CORD blocks hold above $96$, and the run reaches $85.9$. The weakest cell is FUNSD session~2 ($46$--$48$ through the SROIE and CORD sessions, $75.0$ after the revisit). Across schemas, isolation by deltas does not replace the memory, and CoLaR-SBR ($\nSbrMix$ in the main table) remains the better method on Mixed; one seed.

\section{Analysis of the background conflict}
\label{app:conflict}
\paragraph{Takeaway.} Repairs that change only the labels the memory and the current documents supervise move CIL-CORD AA from $\nColar$ (CoLaR) to at most $\nLabelRepairMax$ on any seed without changing what the memory stores; a session-blocked readout with the same memory moves it to $\nSbr$; and the readout without a memory, or on an almost frozen trunk (only the last layer and the readout plastic), does not. The conflict is in the labels, and its remedy is in the readout. \cref{tab:conflict} lists the runs with their seeds.

\paragraph{Stale labels in the memory.} A document stored at session $t$ labels every entity of a later session ``O''. Refreshing the memory with the true labels at each boundary rewrites many stored tokens: on Mixed, $3120$--$3307$, $2640$--$2932$, $0$ and $305$--$316$ tokens at the four refreshes ($50$, $100$, $150$ and $200$ stored documents; three seeds, earlier grid, legacy scoring). A deployable variant that refreshes with the model's own confident predictions rewrites $0/0/0/84$ tokens on seed 42, none on seed 7 and $7/0/0/36$ on seed 123 ($84$ against the $6{,}076$ that the true-label refresh rewrites on seed 42): the model is confident on almost no stale-``O'' token, so the pseudo-label refresh is a no-op (falsification ledger, \cref{tab:ledger}). On CIL-CORD the true-label refresh rewrites $101/760/1461/1402$, $66/944/1366/1269$ and $74/943/1315/1110$ tokens at its four refreshes on seeds 42, 7 and 123 (earlier grid). The refresh runs at the end of each session and gives the stored documents the true labels of every class seen so far; it cannot cover the session trained next, whose entities stay ``O'' in the stored documents while it is trained. Under the clean protocol (\nOracleScope) it rewrites $\nOracleRelabel$ tokens on seed 42 and reaches $\nOracleFull$ full-label F1 and $\nOracle$ AA, against $\nColarSeedFull$ and $\nColarSeed$ for CoLaR without the refresh and $\nJointSeedFull$ and $\nJointSeed$ for joint training on the same seed: $\nOracleShareFull\%$ of the gap in full-label F1 and $\nOracleShare\%$ in AA. It stays below CoLaR-SBR on every seed under both metrics. The legacy gate run of the same seed, which early-stopped on the test split, reached $\nOracleGate$ AA. The refresh is not deployable, since it reads labels that a continual learner never sees.

\paragraph{Why the two metrics disagree on the refresh.} In the clean run sessions~3 to~5 are learned only to $\nOracleLateMin$ to $\nOracleLateMax$ F1 on their own diagonal; sessions~3 and~4 rise to $\nOracleNextMin$ to $\nOracleNextMax$ one session later, when their own documents enter the memory and the older ones are refreshed, and the last session ends at $\nOracleLast$. The run does not separate these two contributions. AA weights the five sessions equally, whereas full-label F1 counts entities: the last session holds $\nOracleLastShare\%$ of the entities of the CORD test set, so its low final F1 costs AA far more than full-label F1.

\paragraph{Stale labels in the current documents.} Current documents label every older entity ``O''. Slicing only the replay loss to the classes alive at storage gives $\nSlicedReplay$ on average over two fp16 rescore seeds ($\nSlicedReplayGate$ on the fp32 gate run of seed 42); slicing the current loss as well (an ``O'' token of the current batch is trained only against $\mathrm{O}$ and the new classes) reaches about $60$ on average over three seeds, with a $20$-point spread between seeds. Adding pseudo-labels on top, in one direction or both, does not help ($48.0$ and $44.1$, one seed each). Each of these acts on the shared background logit, and each leaves it pulled in two directions on look-alike price fields.

\paragraph{The readout without the memory, and the memory without plasticity.} SBR without a memory scores $\vNoBank$ (three clean seeds) and $\vNoBankFull$ full-label F1: the labels are consistent within each block, but the trunk drifts and every old session ends at or below $\nobankOldMax$ F1 after the last session, on every seed (\cref{tab:conflict} gives the AA per seed). With every encoder layer but the last frozen after the first session and no memory, SBR scores $14.8$ (one seed): sessions~3 to~5 are learned poorly or not at all ($4.3$, $22.0$ and $0.0$ on the diagonal) while session~2 is learned at $87.0$ on the same trunk. A likely reading is that old blocks out-vote the new ones on surface-identical prices unless the trunk can adapt; the run does not separate this from a block that cannot fit on an almost frozen trunk (only the last layer and the readout plastic). Both plasticity and the memory are needed, and the blocked readout is what lets them combine.

\paragraph{Readout calibration.} What SBR still loses to joint training is not a calibration error of the block competition. On the fp16 rescore run of CoLaR-SBR (CIL-CORD, seed 42, AA $85.2$), the best global threshold gives $85.4$ and a threshold plus a per-block bias tuned on the test set itself gives $85.8$, so calibration is worth at most $0.6$ (one seed). On DIL, with one block, tuning the threshold gains at most $0.7$ and the test-set oracle at most $1.1$. The remaining loss is retention of early sessions (\cref{tab:matrices}), which SBR-Recall removes.

\section{Analysis of drift}
\label{app:drift}

\subsection{The evidence behind Sec.~4.1 of the main paper}
\label{app:driftbody}
\paragraph{Takeaway.} The main paper states drift briefly because it is the known cause; this subsection holds the measurements it summarises.

\paragraph{Where it sits.} Per-token CKA between consecutive checkpoints is $1.00$ at the embeddings, $0.78$ over the early layers, $0.34$ in the middle, $0.25$ at the last layer and $0.16$ at the classifier, with the same profile on all four backbones. Under LayoutLMv3 modality masks the full, text+layout and text-only models forget comparably (BWT $-89.8$ and $-87.2$ over three seeds, $-79.1$ over the two live text-only seeds); the model without text forgets least ($-66.7$ over three seeds). Old-task-Fisher-weighted displacement is two to three orders of magnitude larger at the classifier than in any encoder bucket, a ratio inflated by construction; inside the encoder it sits in the early and middle layers (\cref{tab:depthprofile}).

\paragraph{Freezing.} Freezing the whole network after the first task gives AA $41.1$ with BWT $0.0$ on DIL: nothing is forgotten and nothing is learned. Freezing only the head and late layers, with the early and middle encoder plastic, gives AA $38.8$ and BWT $-76.8$, the naive level, while early-layer CKA falls from ${\approx}1.0$ to $0.19$ (seed 42).

\paragraph{Methods without old-task supervision.} EWC and LwF stay within $12$ points of naive training and at least $27$ below joint training in every run of Tab.~1 of the main paper. Of the five families we built or ported that keep updating a shared network with no stored old-task targets (\cref{tab:ledger}), head merging is a no-op ($21.6$ against $21.9$ unmerged at its operating point), merging with realignment reaches $43.9$, subspace transfer $39.8$, head slots $42.2$, and feature-Gaussian replay $66.0$ by recovering the densely labelled task only, against $41.3$ for naive training and $88$ for replay. Where we measured the mechanism, on naive training and LwF, the head's output marginal on old tasks snaps to the just-trained task's marginal (cosine $0.997$--$0.998$, against $0.60$ to the old task's own), and classes that are never re-exercised fall to exactly $0.0$ F1. Five post-hoc corrections of that marginal, each with a pass bar fixed before the run, recover at most $-0.1$ AA, because old-class probability mass is ${\sim}10^{-6}$.

\paragraph{The size of a remedy's benefit is backbone-dependent; the cause is not.} The gap between joint and naive training on Mixed agrees to $2.5$ points across the four backbones, whereas the benefit of EWC over naive training spans $17$ points and changes sign ($-11.9$ on LayoutLMv3, $-2.6$ on LiLT, $+3.5$ on BROS, $+5.2$ on BERT; legacy scoring, \cref{tab:grid}, \cref{fig:signflip}). A single-backbone comparison of methods without old-task supervision can land on either side of zero, which is why Tab.~1 of the main paper reports four backbones.

\paragraph{Images.} On ViT-B/16 image class-incremental learning (CIFAR-100, ImageNet-R; \cref{app:image}) a class-conditional Gaussian head (SLCA, $87.5/65.0$) beats the same latent memory ($80.0/55.1$), and a ridge readout refit on the trained trunk reaches $88.3/72.3$: there the trunk is intact and only readout statistics are stale. An image carries one label, so a per-class statistic summarises its readout; a document carries one label per token bound to a position, and the Gaussian analogue is null on documents in every form we tried ($39.4$ as a store).

\subsection{Displacement by depth}
\paragraph{Takeaway.} The classifier is where old-task-weighted parameters move most, but that ratio is inflated by construction; inside the encoder, weighted displacement sits in the early and middle layers, so ``late layers'' is a statement about representations only.

For a checkpoint pair $(\theta^{(t-1)},\theta^{(t)})$ and a parameter group $g$ we compute the old-task-Fisher-weighted displacement $D_g=\sum_{\phi\in g}F^{(t-1)}_\phi(\theta^{(t)}_\phi-\theta^{(t-1)}_\phi)^2$. \cref{tab:depthprofile} reports it at the first task boundary, mean over the live seeds of each condition, and \cref{fig:displacement} shows the profile. The classifier's $D_g$ is two to three orders of magnitude above the largest encoder bucket on every condition ($111\times$ to $1608\times$). The empirical Fisher of a token classifier is largest at the head whatever the task ($0.22$ against $0.005$ for the next group on LayoutLMv3), so the weighting itself favours the head. The informative part is the encoder-only share: with the head excluded, weighted displacement sits in the early and middle layers on every document encoder and is smallest in the late layers. Representational drift measured by CKA, in contrast, grows with depth because it accumulates. The two instruments agree on the classifier and disagree on the late encoder layers, and the main text claims only what both support.

\subsection{What the significance tests do and do not show}
\paragraph{Takeaway.} Neither test is evidence for the localisation or for architecture-generality; those rest on the descriptive agreement of the profiles and on the remedy ordering.

Two tests accompanied an earlier version of this analysis and we report them with their limits. (i) A Mann--Whitney test of the classifier against each other parameter group (six samples per group, Bonferroni $\alpha'=0.0042$) rejects equality against three of twelve groups ($p=0.0022$) and not against the rest; it was run on per-group Fisher \emph{importance}, which is head-dominant by construction, and we do not use it as evidence of where forgetting occurs. (ii) A permutation test on the normalised $D_g$ depth profile does not reject a shared profile between LayoutLMv3 and LiLT or BROS ($p=0.38$, $0.51$); since every normalised profile is nearly one-hot at the head, this test cannot reject and is not evidence of architecture-generality. The claim that drift is shared across backbones rests on the descriptive agreement of the CKA profiles and of \cref{tab:depthprofile}, and on the remedy ordering of \cref{tab:grid}.

\subsection{Consolidation probe}
\paragraph{Takeaway.} A uniform depth penalty prevents learning; the probe does not show that a targeted penalty recovers old tasks without replay.

A depth-targeted consolidation method (output distillation with a per-bucket penalty) scores $42.6$ AA on DIL when the penalty is spread uniformly over all depth buckets, $84.7$ when concentrated on the head and late layers, $86.1$ head-only and $86.2$ late-only (three seeds). All four arms include a $200$-document head-replay buffer, and plain ER with the same buffer scores $87.9$. We do not cite the probe for recovery without replay.

\subsection{Remedy benefit across backbones}
\paragraph{Takeaway.} The cause is shared by four encoders; the benefit of a remedy without old-task supervision is not, and can change sign.

\cref{fig:signflip} plots, per backbone and scenario, the change in AA over naive training of each classical remedy, from the earlier grid (\cref{tab:grid}; legacy scoring on CIL-CORD and Mixed). Replay's benefit is large and consistent; EWC and LwF change sign across backbones, which is why the main paper's drift table reports four backbones.

\subsection{What the memory must hold}
\label{app:ladder}
\paragraph{Takeaway.} Whole documents retain and every summary of the same store collapses; each document can then be compressed on its own (\cref{fig:colar,fig:ladder}).

\paragraph{Routing which stored document to replay (null).} The OCR vocabulary of a document is set by the input and does not drift with training, which suggests a drift-free sampler: a softmax over term-frequency signature scores $s_j=\sigma(x)^{\top}\sigma_j$ in three directions (\emph{near}, \emph{far}, \emph{task}), uniform as the zero-point. The seed-42 reading was promising (far $+1.8$ over uniform $86.4$ at $d{=}50$), so we fixed that single arm in advance for confirmation. Across three seeds the gap collapses to $+1.8/+0.4/-0.6$, mean $+0.5$ points with a sign flip, inside the uniform-sampling spread: lexical routing is a null, and the CoLaR results do not depend on it.

\paragraph{Rebalancing and reading the memory (nulls).} On DIL with LayoutLMv3 (CoLaR, $k{=}4$, $r{=}128$, $50$ documents per task; base $87.6$ on seed 42), three changes to how the memory is filled or weighted leave AA where it was: a class-balanced replay loss gives $87.1$, coverage-based ($k$-centre) document selection $86.8$ and entity-weighted compression $87.1$ (seed 42 each). Each trades FUNSD retention for SROIE retention at about $1{:}1$, so the changes redistribute retention between tasks rather than add to it. A three-seed check finds no lever above the base (class-balanced $87.8$, $k$-centre $87.0$, against $\vColarDil$ for the base). Two read-side additions are negative: blending a $k$NN readout over the stored latents into the head is inert or harmful, and metaplastic consolidation of the readout lowers AA from $85.9$ to $79.5$ at its own operating point.

\paragraph{Budget-adaptive allocation is a frontier, not a gain.} Allocating a fixed compressed-replay budget unevenly across tasks (documents $[18,5,2]$, ranks $[64,128,64]$ vs.\ a uniform $10$ documents at rank $64$; 5 epochs, $k{=}4$) gave $+4.0$ AA on seed 42 while passing a per-domain guard fixed in advance. On seeds 7 and 123 the same comparison gave $-8.0$ and $+5.7$: $+0.6\pm7.5$ over three seeds, a null. The seed-42 result was a point on a Pareto frontier (old-domain retention traded against the final domain at $\approx9{:}1$), not a shift of the frontier, and we report it as such.

\paragraph{A bounded positive on the storage side.} Replaying pseudo-labelled \emph{public} documents through the same mechanism (zero private bytes) recovers dense-label tasks (FUNSD $76.1$) but not one the proxy pool does not cover (SROIE $\sim7$), topping out at $58.9$: coverage-limited transfer.

\paragraph{Hyperparameters.} Documents: AdamW, learning rate $5{\times}10^{-5}$ (constant), weight decay $0.01$, gradient clipping $1.0$, batch size $2$ with gradient checkpointing, early stopping with patience $2$ and $\delta{=}0.1$ F1 points with best-weight restoration. Image CIL (CIFAR-100, ImageNet-R; ViT-B/16, ten sessions): every reported cell, including the frozen-backbone and replay baselines, was trained on a 6\,GB GPU at batch size 16 in fp32 with gradient checkpointing, 100-epoch cap with early stopping (patience 2), seeds 42/7/123; the CODA-Prompt, CL-LoRA and LCA image cells use this recipe unchanged.

\paragraph{Seeds and hardware.} Seeds 42, 7 and 123 for every three-seed cell; a cell with fewer seeds shows its per-seed values. \paragraph{Wall-clock.} \cref{tab:perseed} gives the mean training-loop time per run of every headline cell, recorded by each run (the sum of the per-session training times). The h/run column of \cref{tab:perseed} gives these times for every headline cell on this card; the joint-training reference takes well under an hour because it is one pooled run.
